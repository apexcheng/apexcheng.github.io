# Redesign Existing Projects

项目适配自 `Leonxlnx/taste-skill` 的 `redesign-existing-projects`，参考版本：`ccbc15639c97057cbfcf32ecebc38ef716e4bb37`。

目标：先理解现有页面为什么成立或不成立，再做针对性升级。不是默认重写，也不是只做表面 CSS 修补。

## 使用条件

适合：

- 用户明确说视觉审查、重新设计、重构页面、增强视觉表达。
- 页面存在明显的信息层级、布局、长文阅读、响应式或交互问题。
- 旧 DOM / 组件 / CSS 已经阻碍当前设计目标，需要在需求边界内重构。

不适合：

- 改字、事实修正、链接、frontmatter。
- 小范围样式 bug。
- 已经有明确、批准的视觉方案，只需要照方案实现。

## 执行顺序

### 1. Scan

只读取当前页面和完成任务需要的项目规则：

- 页面内容和信息关系。
- 当前组件、CSS、主题和响应式方式。
- 是否已有文章专属视觉语言。
- 现有交互、锚点、目录、代码块和移动端行为。

### 2. Diagnose

从读者视角判断问题，不机械套审计清单：

- 阅读顺序是否自然，重点是否明确。
- 视觉块是否真的承担信息表达。
- 是否卡片过多、布局重复、装饰多于信息。
- 长正文宽度、行高、间距和章节节奏是否舒服。
- 公式、流程、对比、数据关系是否应该用更直观的结构。
- 桌面与移动端是否都能理解，而不是仅仅“没有溢出”。
- 动效是否帮助叙事或交互，还是制造噪音。

### 3. Decide scope

优先最小但完整的方案：

- 只是层级问题：调整排版、间距、颜色语义。
- 视觉块表达错误：重做对应视觉结构。
- DOM / 组件结构阻碍目标：允许重构直接相关部分。
- 整页视觉概念错误：用户要求重设计时可以整体重构，但保留正确内容和功能。

不要为了减少 diff 保留明显不合适的结构，也不要借重设计修改无关页面。

### 4. Fix

优先级通常是：

1. 信息关系与阅读顺序。
2. 版面层级与正文可读性。
3. 关键视觉结构。
4. 响应式转换。
5. 交互与动效。
6. 表面材质和细节润色。

不要从“换字体”“加渐变”“加阴影”开始。

## 常见需要修正的 AI 页面模式

- 所有内容都变成边框卡片。
- 三列等宽卡片反复出现。
- 每节同样的 eyebrow + 标题 + 卡片网格。
- 只有左右图文交替，没有节奏变化。
- 纯装饰的标签、编号、状态点、假数据和伪系统信息。
- 为了视觉冲击牺牲正文阅读和移动端。
- 过多玻璃、渐变、发光、噪点和无意义动效。

这些是诊断信号，不是看到就必须删除；仍以文章内容和既有视觉概念为准。

## 必须保留的东西

除非用户明确要求，不静默修改：

- URL / slug、主要导航和文章信息架构。
- 正确的正文事实、公式、代码和示例。
- 已有主题系统和品牌资产。
- 锚点、目录、SEO、可访问性和现有功能。
- 与其他文章共享且工作正常的全局组件行为。

## 验证

复杂视觉改造完成后至少验证：

- 构建通过。
- 桌面端阅读顺序和视觉重点。
- 移动端布局、文字尺寸、横向关系转换和交互。
- 页面没有因为设计升级破坏内容、锚点、目录或功能。
