# Image to Code

项目适配自 `Leonxlnx/taste-skill` 的 `image-to-code`，参考版本：`ccbc15639c97057cbfcf32ecebc38ef716e4bb37`。

本 Skill 解决的是“有明确视觉参考，如何准确落成网页”，不是博客高视觉文章的默认设计流程。

## 触发条件

只有以下情况使用：

1. 用户提供截图、设计稿、参考图，并要求实现或复现。
2. 用户明确指定先生成设计图，再按图开发。
3. 已经确定视觉方向，需要通过图像参考提高实现一致性。

以下情况不要使用：

- 只是因为文章属于“高视觉文章”。
- 普通文章视觉设计或现有页面审查。
- 已经有清楚的 MDX / CSS 实现方案，不需要图像中间层。

## 项目优先级

1. 用户明确要求。
2. `AGENTS.md` 与 `docs/ARTICLE_VISUAL_SYSTEM.md`。
3. 已有文章内容、主题、组件和视觉语言。
4. 当前视觉参考图。
5. 本 Skill 的通用实现建议。

视觉图不能覆盖事实内容、公式、代码、文章结构或项目约束。

## 工作流

### A. 用户已经提供图片

直接把图片当作视觉参考，不额外生成设计图。

分析：

- 页面或区块的主视觉焦点。
- 信息层级和阅读顺序。
- 网格、对齐、留白、边距和内部间距。
- 字体大小关系、字重、行数和换行方式。
- 背景、强调色、边框、圆角、阴影和材质。
- 图片比例、裁切、蒙版和图文关系。
- 按钮、标签、卡片和其他组件的视觉规则。
- 哪些细节属于风格，哪些只是图片中的偶然结果。
- 桌面图如何合理转换到移动端。

然后在现有 Astro / MDX / CSS 体系中实现，不迁移框架。

### B. 用户明确要求 image-first

如果当前 Agent 有图像生成能力：

1. 先根据博客视觉规则确定内容关系和设计方向。
2. 只生成足够帮助实现的视觉参考，不机械“一节一张图”。
3. 复杂区块看不清时，优先生成新的局部清晰参考，而不是从大图粗暴裁切。
4. 分析视觉参考后再写代码。

如果当前执行环境没有图像生成能力，不伪造“已生成设计图”；直接说明限制，并继续使用已有视觉参考或项目规则完成实现。

## 分析要求

不要只总结“高级、简洁、现代”等气质词。至少提取：

- 结构：区块顺序、列宽、对齐、层级。
- Typography：字号比例、字重、行高、字距、正文宽度。
- Spacing：区块间距、边距、卡片内距、图文距离。
- Color：背景、正文、次级文字、强调色和边界色的关系。
- Components：按钮、卡片、标签、媒体框的形状和状态。
- Media：图片比例、裁切逻辑和视觉重心。
- Motion：如果图片或说明暗示动画，只实现有明确意义的部分。

## 实现原则

- 追求“视觉逻辑一致”，而不是逐像素硬抄导致响应式失效。
- 不把图片里的装饰性假数据、假状态、假标签带进正式文章。
- 可复制文字仍然使用真实 HTML / MDX 文本，不把正文烘焙进图片。
- 公式、流程、表格、代码等需要真实语义和可访问性。
- 尽量复用项目现有组件与 CSS 模式。
- 不为了匹配截图擅自增加依赖。
- 图片参考与文章内容冲突时，以正确内容和阅读理解优先。

## 防止实现漂移

落地时持续检查：

- 是否把独特布局偷偷简化回通用卡片网格。
- 是否把原本的留白压缩得过密。
- 是否把字体层级改成项目默认而丢失视觉重点。
- 是否重复使用同一种区块结构，破坏参考图节奏。
- 是否为了“更好实现”改变了参考图真正重要的比例和关系。

## 完成检查

- 视觉参考中的主要层级、比例和节奏是否保留。
- 实现是否仍符合博客自己的文章视觉系统。
- 正文、代码、公式和链接仍然是真实可访问内容。
- 桌面端和移动端都成立。
- 没有为了复现图片引入不必要框架、依赖或全局风格改变。
