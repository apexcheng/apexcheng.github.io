# 开发规则

本文件负责代码、样式、构建、测试、依赖、工程结构和 Git 协作。

## 修改原则

```text
最小改动 | 结构简单 | 保持现有风格 | 不做无关重构
```

1. 在当前实际环境和仓库根目录执行命令。
2. 修改前读取相关文件，不凭文件名或旧经验直接改。
3. 只修改当前任务直接相关的内容。
4. 不做无关格式化、改名、重构或依赖升级。
5. 不引入不必要的依赖、抽象层或配置层。
6. 保留用户已有改动；发现无关问题可以说明，但不扩大修改范围。

## 代码风格

1. 优先简单、直接、可读的实现。
2. 保持现有命名、数据流和项目结构。
3. 一次性逻辑不提前抽象；只有真实复用或明显降低理解成本时才提取。
4. 注释只解释不直观的业务行为、边界或技术原因。

## 项目边界

- 正式文章：`src/content/posts/`
- 视觉实验 / Demo：`src/content/posts/visual-lab/`
- Agent 规则和索引：`docs/`

文章任务按 `docs/writing/BLOG_AGENT.md` 执行。

## 验证

1. 修改代码、样式或配置后，运行当前环境中可用的相关测试或构建。
2. 只改文档时可以不运行构建。
3. 无法运行验证时直接说明原因，不安装环境，不把静态阅读描述成运行通过。
4. 只有复杂布局或视觉 CSS 改动才需要检查桌面端和移动端页面。

## Git

1. 默认目标分支是 `main`。
2. commit、push、部署和新建分支仅在用户明确要求时执行。
3. 不使用会丢弃用户改动的 Git 命令。
