# 开发规则

本文件负责代码、样式、构建、测试、依赖、工程结构和 Git 协作。

## 修改原则

最小改动、已有工作区保护及环境约束遵循 `AGENTS.md`；本文件补充工程实现边界：

1. 不引入不必要的依赖、抽象层或配置项，不做无关依赖升级。
2. 当旧结构阻碍当前目标时，可在需求边界内调整组件、DOM、样式组织或动画实现，不必为了缩小 diff 保留不合理结构。
3. UI 重设计或复杂交互可以进行必要的相关重构，但不能借机改动无关业务逻辑、数据层或路由。

## 代码风格

1. 优先简单、直接、可读的实现。
2. 保持现有命名、数据流和项目结构。
3. 一次性逻辑不提前抽象；只有真实复用或明显降低理解成本时才提取。
4. 注释只解释不直观的业务行为、边界或技术原因。

## 文章浏览与阅读交互约定

以下是已上线的站点交互行为，调整相关页面时保持一致：

1. **内容入口**：顶部导航只保留「文章」；`/articles/` 与 `/series/` 通过「独立文章 / 专题系列」切换，系列学习路线和原有 URL 继续保留。
2. **文章列表**：`/articles/` 默认只展示不属于系列、未归档、非视觉实验室的公开文章；选择「视觉实验室」分类时单独展示实验文章，普通搜索及「全部分类」不混入实验内容。精选为快捷切换按钮，归档在次级筛选菜单中，均可与搜索、分类、排序组合。URL 参数为 `featured=1`、`archived=1`，刷新时恢复；历史链接 `series=1` 仍可展示包含系列文章的列表，但不再单独提供该开关。分类计数随系列及归档状态变化，不受关键词搜索及精选状态影响。归档文章保留详情页原 URL，但退出首页、站内搜索、分类与系列目录、相关推荐、RSS、Sitemap 等默认入口；没有网页删除操作。
3. **正文侧栏**：桌面端按「文章信息 / 文章目录」排列，两个区块可分别折叠；文章信息默认收起，文章目录默认展开。长目录独立滚动并高亮当前章节，保留收起整个侧栏的专注模式；窄屏沿用正文内目录。目录底部留有滚动余量，避免末尾链接难以阅读。
4. **阅读主题**：仅保留「素纸」（`visual-system`）、「清晰经典」（`clarity`）、「玄墨」（`classic`）。浏览器旧偏好 `index-gradient` 回退至「素纸」；不要恢复已删除的「晨曦」主题。旧首页实验页面不因本约定删除。

## 验证

1. 修改代码、样式或配置后，运行当前环境中可用的相关测试或构建。
2. 只改文档时可以不运行构建。
3. 无法运行验证时直接说明原因，不安装环境，不把静态阅读描述成运行通过。
4. 文章页面的视觉验收触发条件见 `docs/writing/BLOG_AGENT.md`，不要把构建成功当成浏览器验收。

## Git

提交、推送和部署权限及工作区保护遵循 `AGENTS.md`；新建分支同样须用户明确要求。
