# 开发规则

本文件负责代码、样式、构建、测试、依赖、工程结构和 Git 协作。

## 修改原则

```text
默认最小改动 | 目标完整 | 结构简单 | 不做无关重构
```

1. 在当前实际环境和仓库根目录执行命令。
2. 修改前读取相关文件，不凭文件名或旧经验直接改。
3. 只修改当前任务直接相关的内容。
4. 不做无关格式化、改名、重构或依赖升级。
5. 不引入不必要的依赖、抽象层或配置层。
6. 保留用户已有改动；发现无关问题可以说明，但不扩大修改范围。
7. 默认优先最小、直接的修改；但当现有结构明显阻碍当前功能、交互或视觉目标时，可以在需求边界内调整组件、DOM、样式组织或动画实现，不要求为了减少 diff 保留不合适的旧结构。
8. UI 重设计、复杂交互和视觉系统升级以完成设计目标为优先；允许必要的相关重构，但不得借机改动无关业务逻辑、数据层、路由或其他页面。

## 代码风格

1. 优先简单、直接、可读的实现。
2. 保持现有命名、数据流和项目结构。
3. 一次性逻辑不提前抽象；只有真实复用或明显降低理解成本时才提取。
4. 注释只解释不直观的业务行为、边界或技术原因。

## 项目边界

- 正式文章：`src/content/posts/`
- 视觉实验 / Demo：`src/content/posts/visual-lab/`
- Agent 规则和索引：`docs/`

文章任务按 `docs/writing/BLOG_AGENT.md` 执行。

## 文章浏览与阅读交互约定

以下是已上线的站点交互行为，调整相关页面时保持一致：

1. **内容入口**：顶部导航只保留「文章」；`/articles/` 与 `/series/` 通过「全部文章 / 专题系列」切换，系列学习路线和原有 URL 继续保留。
2. **文章列表**：`/articles/` 默认只展示不属于系列的公开文章；「包含系列文章」默认不勾选，勾选后系列文章参与当前列表的搜索、分类和排序。分类数量与可见范围保持一致，切换状态可由 URL 参数 `series=1` 恢复。
3. **正文侧栏**：桌面端按「文章信息 / 文章目录」排列，两个区块可分别折叠；文章信息默认收起，文章目录默认展开。长目录独立滚动并高亮当前章节，保留收起整个侧栏的专注模式；窄屏沿用正文内目录。目录底部留有滚动余量，避免末尾链接难以阅读。
4. **阅读主题**：仅保留「素纸」（`visual-system`）、「清晰经典」（`clarity`）、「玄墨」（`classic`）。浏览器旧偏好 `index-gradient` 回退至「素纸」；不要恢复已删除的「晨曦」主题。旧首页实验页面不因本约定删除。

## 验证

1. 修改代码、样式或配置后，运行当前环境中可用的相关测试或构建。
2. 只改文档时可以不运行构建。
3. 无法运行验证时直接说明原因，不安装环境，不把静态阅读描述成运行通过。
4. 只有复杂布局或视觉 CSS 改动才需要检查桌面端和移动端页面。

## Git

1. 默认目标分支是 `main`。
2. commit、push、部署和新建分支仅在用户明确要求时执行。
3. 不使用会丢弃用户改动的 Git 命令。
