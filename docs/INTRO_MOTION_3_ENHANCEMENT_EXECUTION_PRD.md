# 天体序章增强开发执行 PRD

## 1. 执行目标

本文件负责把《天体序章增强 PRD》转化为开发执行清单。

目标是在不破坏现有自动镜头、自由探索、手势、返回落版和博客入口逻辑的前提下，通过最小范围修改增加空间密度、经过事件和知识宇宙内容映射。

产品方向以 `docs/INTRO_MOTION_3_ENHANCEMENT_PRD.md` 为准。

## 2. 修改范围

主要修改文件：

- `src/scripts/intro-motion-3.js`
- `src/pages/intro-motion-3.astro`

原则：

- 不引入新的大型依赖。
- 不重构现有开屏架构。
- 不拆出多层抽象或宇宙引擎。
- 只在真实复用或明显降低理解成本时增加辅助函数。
- 优先复用现有 Three.js 场景、材质、时间轴和设备判断逻辑。

## 3. 第一批：空间充实

### P0-1 分层星场增强

开发内容：

- 保留现有星场。
- 增加一层更远、更细、更密的背景星点。
- 增加一层数量更少、体积略大的中近景星点。
- 不同层使用不同闪烁幅度和速度。
- 闪烁需低频、随机，禁止同步呼吸。

实现建议：

- 优先使用 `THREE.Points + BufferGeometry`。
- 每层一次批量渲染，不为单颗星创建独立 Mesh。

验证点：

- 静态截图中纯黑空洞区域明显减少。
- 转动镜头时能感受到远近层次。
- 不出现“雪花”或“粒子雨”。

性能风险：低。

### P0-2 星云 / 宇宙尘埃背景

开发内容：

- 增加 2～3 个大尺度、极淡的星云区域。
- 可使用透明 Sprite、低成本 Shader 或简单噪声平面。
- 每层放在不同深度。
- 仅做缓慢漂移或亮度呼吸。

建议分布：

- 太阳附近：偏暖、非常弱的雾带。
- 左下深空：偏冷蓝紫结构。
- 远景中央：灰蓝尘埃层。

验证点：

- 黑色宇宙仍是主色。
- 星云只提供结构，不形成贴图墙。
- 不覆盖行星轮廓和最终标题。

性能风险：中低。

### P0-3 近景漂浮粒子

开发内容：

- 在相机周围大范围布置少量微尘。
- 缓慢漂移。
- 利用相机移动产生视差。

数量建议：

- 桌面：80～160
- 移动端：40～80

验证点：

- 静止时大部分粒子不抢注意力。
- 镜头移动和自由探索时空间深度明显增强。

性能风险：低。

### P0-4 低频流星 / 彗星

开发内容：

- 自动镜头固定安排 1～2 次流星事件。
- 每次持续约 0.6～1.2 秒。
- 使用短尾迹快速划过远景或中景。
- 自动镜头使用固定时间和路径，避免每次随机影响分镜。

建议时机：

- 第一次：约 3 秒
- 第二次：约 8～9 秒

验证点：

- 流星可被注意到，但不是视觉主角。
- 不穿过标题主区域。
- 不形成连续流星雨。

性能风险：低。

## 4. 第二批：经过感增强

### P0-5 卫星 / 探测器掠过

开发内容：

- 使用基础 Geometry 拼装一个轻量人工卫星或深空探测器。
- 主体可由 `BoxGeometry / CylinderGeometry / PlaneGeometry` 组成。
- 包含主体、太阳能板、简化天线即可。
- 不加载外部 GLTF 模型。

分镜：

- 建议在 2.7～3.8 秒之间从镜头前景快速掠过。
- 从画面一侧进入并离开。
- 可增加一次极弱导航灯或太阳能板高光变化。

验证点：

- 关闭字幕后，这一段仍然明显存在“发生了一件事”的感觉。
- 不遮挡地球、太阳或主要文案。

性能风险：低。

### P0-6 轨道觉醒动画

开发内容：

- 不让全部轨道一开始完全可见。
- 根据章节逐步提高轨道透明度。
- 内轨先出现，外轨后出现。
- 可选择 1～2 条轨道加入轻量光点沿线移动。

时间建议：

- 4.5 秒：内轨开始出现
- 6 秒：更多轨道展开
- 7.5 秒后：太阳系主要轨道完整呈现

验证点：

- “太阳系展开”章节和画面结构变化明显对应。
- 最终轨道仍然保持克制，不像 HUD 网格。

性能风险：低。

## 5. 第三批：高潮增强

### P1-1 小行星带局部穿越

开发内容：

- 优先复用现有 asteroid 体系。
- 在火星和木星区域增强局部小行星密度。
- 只让镜头穿过其中一个局部切片。
- 少量岩石可以靠近镜头产生明显视差。

数量建议：

- 桌面：120～240
- 移动端：约桌面一半

视觉要求：

- 大多数小行星保持暗色。
- 只有少数具有太阳侧光。
- 不允许大量发光。
- 不允许突然占满屏幕。

验证点：

- 7～9 秒附近内容密度明显提高。
- 太阳系全景展开后画面重新变干净。

性能风险：中。

### P1-2 太阳活动事件

开发内容：

- 在现有太阳发光基础上增加一次短暂高潮。
- 可组合：光晕扩大、Bloom 增强、Lens flare 微增、极淡弧形耀斑。

建议时机：

- 约 8 秒，太阳系展开前后。

持续时间：

- 0.8～1.4 秒。

验证点：

- 自动镜头有一次明确光效峰值。
- 峰值结束后恢复，不长期爆亮。

性能风险：低到中。

## 6. 第四批：知识宇宙内容映射

### P0-7 博客分类星群

固定内容：

- 教程
- 实践
- 生活
- 视觉实验室

开发内容：

- 在最终 15%～20% 时间段逐个淡入。
- 以空间坐标 / 星群标签形式分布在不同位置。
- 每个标签附近可配置 2～5 个小星点。
- 可选极细连接线，但不要形成卡片或导航菜单。

建议示意：

```text
       · 教程

                    · 实践

   · 生活

                         · 视觉实验室
```

实现位置：

- 文本 DOM 与响应式 CSS 优先放在 `src/pages/intro-motion-3.astro`。
- 时间驱动透明度和状态切换由 `src/scripts/intro-motion-3.js` 控制。

验证点：

- 最终画面能感受到“内容分类存在于宇宙中”。
- 仍然由博客标题和“进入博客”按钮主导。

性能风险：极低。

### P1-3 长期主题信号

候选内容：

- Python
- Agent
- 自动化
- 数据处理
- 电商运营
- 可视化表达

开发内容：

- 选择 4～6 个长期主题。
- 字号小于正式分类。
- 透明度低于正式分类。
- 只在最终 15% 自动镜头和自由探索状态出现。

验收原则：

> 第一眼看不到全部主题，认真看时才发现。

性能风险：极低。

## 7. 自由探索状态

自动镜头新增元素在自由探索中继续保留，但不增加新的功能系统。

保持：

- 星云缓慢移动
- 星点低频闪烁
- 微尘漂浮
- 小行星缓慢运动
- 分类星群可略微增强
- 主题信号可略微增强

可选：

- 流星以 15～30 秒一次的低频随机事件出现

不增加：

- 点击交互
- 详情面板
- 内容导航
- HUD

## 8. 移动端降级

开发前即按设备降级，不在最后补救。

移动端保留：

- 星场
- 2 层星云
- 少量近景粒子
- 卫星
- 至少一次流星
- 轨道觉醒
- 分类星群

移动端降低：

- 小行星数量约 50%
- 近景粒子数量约 50%
- 星云 3 层时降为 2 层
- 不额外增加 Bloom 强度
- 不使用大量实时阴影
- 不引入体积雾

## 9. 推荐执行顺序

### 第 1 批

- 分层星场
- 星云
- 近景微尘

验证点：

> 截图是否明显更充实，同时太阳、地球和行星仍然突出。

### 第 2 批

- 卫星 / 探测器掠过
- 流星
- 轨道觉醒

验证点：

> 12 秒镜头是否出现明确“事件节奏”。

### 第 3 批

- 小行星带
- 太阳光效高潮

验证点：

> 高潮段是否丰富但不混乱；移动端是否仍然流畅。

### 第 4 批

- 分类星群
- 长期主题信号
- 最终落版收束

验证点：

> 是否自然从“太阳系”过渡到“个人知识宇宙”。

## 10. 技术边界

继续使用现有能力：

- Three.js
- `Sprite`
- `Points`
- `BufferGeometry`
- `ShaderMaterial`（仅确有必要时）
- `UnrealBloomPass`
- `Lensflare`

禁止为了本轮增强新增：

- 物理引擎
- 外部 GLTF 模型依赖
- 新后处理框架
- 重型粒子库
- 单独的宇宙场景架构层

## 11. 最终验收环境

桌面至少检查：

- 1440px 宽屏
- 1920px 宽屏

移动端至少检查：

- iPhone 纵屏
- iPad 纵屏
- iPad 横屏

## 12. 最终验收问题

每轮完成后从产品视角回答：

1. 第一眼还会不会觉得太空太空？
2. 12 秒里是否每 2～3 秒都有一次明显变化？
3. 新元素有没有抢太阳、地球和标题的注意力？
4. 有没有变成“粒子特效 Demo”？
5. 最后能不能明显感觉这是个人知识宇宙？
6. 移动端是否仍然流畅、清楚？
7. “进入博客”是否仍然是最明确的动作？

如果第 3、4、7 任意一项出现问题，应优先删除或弱化新增元素，而不是继续堆叠参数。
