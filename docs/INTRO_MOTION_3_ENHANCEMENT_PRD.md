# 天体序章增强 PRD

## 1. 文档目的

本 PRD 用于定义「天体序章」下一轮视觉与内容增强方向，重点解决当前场景“太空里太空”、镜头经过感不足、与个人博客内容关联偏弱的问题。

本轮目标不是增加更多功能，而是让现有 12 秒开屏在不牺牲高级感、性能和博客主入口清晰度的前提下，变得更丰富、更有叙事推进感，并更像“黄撑的个人知识宇宙”。

关联页面：

- `src/pages/intro-motion-3.astro`
- `src/scripts/intro-motion-3.js`
- 正式页面：`/intro-motion-3/`

## 2. 产品定位

「天体序章」应当是：

> 一个可观看、可轻交互、带品牌记忆点的个人博客序章。

它不是：

- 纯 Three.js 炫技 Demo
- 重操作小游戏
- 复杂宇宙导航系统
- 博客正文内容的替代品

所有新增设计需要满足以下原则：

1. 博客内容始终是主产品。
2. 新元素用于增加空间层次和经过感，不用于堆料。
3. 自动镜头每 2～3 秒应出现一次可感知的新事件。
4. 动画最后应从“宇宙”自然收束到“个人知识宇宙”。
5. 最终落版必须保持干净，“进入博客”始终是最明确的主动作。

## 3. 当前主要问题

### 3.1 空间内容密度不足

当前主体天体、星场和轨道已经成立，但大面积深空区域缺少层次。用户在自动镜头和自由探索中容易产生“场景有了，但周围太空”的感受。

### 3.2 镜头经过感不够

目前更多是“摄像机经过已有星体”，缺少前景、中景实体掠过和章节事件，因此镜头移动存在，但“飞过了什么”的记忆点偏少。

### 3.3 与博客内容映射不足

现有最终落版能表达“个人知识宇宙”，但场景主体仍然偏通用宇宙视觉。需要在最终阶段加入轻量的博客分类和长期主题信号，让宇宙真正具有个人内容属性。

## 4. 增强框架

本轮新增内容分为 5 层。

### 4.1 远景背景层

目标：解决纯黑区域过空的问题，同时保持深空气质。

计划增加：

- 更细、更密的远景星场
- 少量中景亮星
- 不同步的低频闪烁
- 2～3 个极淡星云 / 宇宙尘埃区域
- 低频流星或彗星事件

设计要求：

- 远景星负责密度，中景星负责深度。
- 星云只做若隐若现的结构，不做明显贴图墙。
- 流星整个自动镜头只出现 1～2 次。
- 禁止形成“雪花”“粒子雨”或高频闪屏感。

### 4.2 中景经过层

目标：增强“镜头真的在穿越空间”的感受。

计划增加：

- 一次卫星 / 深空探测器近景掠过
- 少量漂浮碎石或微型天体
- 一段局部小行星带穿越
- 轨道逐步点亮 / 展开的过程

设计要求：

- 卫星 / 探测器作为明确事件，只出现一次即可。
- 小行星带只做局部高密度片段，不铺满整个太阳系。
- 轨道必须从“静态结构”升级成“被唤醒的系统”。

### 4.3 主体事件层

目标：让 12 秒镜头有清晰节奏，而不是单纯持续飞行。

建议事件：

- 地球城市灯光渐亮
- 云层缓慢漂移
- 大气边缘光增强
- 卫星掠过
- 内行星依次经过
- 轨道逐段点亮
- 小行星带局部穿越
- 太阳光晕 / 耀斑短暂高潮
- 最终知识星群出现

原则：

> 每个章节至少有一个用户能直接感知到的“新事情发生”。

### 4.4 博客内容映射层

目标：让场景从“好看的宇宙”升级为“黄撑的个人知识宇宙”。

第一层使用当前正式分类：

- 教程
- 实践
- 生活
- 视觉实验室

表现形式：

- 空间坐标标签
- 微型星群
- 极细连接线
- 少量伴随光点

禁止使用：

- 大卡片
- 传统导航按钮
- 弹窗
- 长说明文字

第二层可选增加长期主题词：

- Python
- Agent
- 自动化
- 数据处理
- 电商运营
- 可视化表达

主题词应弱于分类词，作为远处“知识信号”存在。

### 4.5 交互反馈层

现有自由探索能力保留：

- 单指 / 鼠标环视
- 双指移动 / 缩放
- 滚轮缩放
- WASD / QE 飞行
- 重置视角
- 返回落版

本轮只增加轻反馈：

- 探索状态下星群和主题信号可略微增强
- 空间粒子继续漂移
- 小行星继续缓慢运动
- 流星可低频随机出现

本轮不新增：

- 星球点击详情
- 文章跳转
- HUD 面板
- 任务系统
- 复杂宇宙导航

## 5. 12 秒分镜增强方案

### Chapter 1：地球微光（0～2.2 秒）

目标：建立“世界正在苏醒”的第一印象。

新增：

- 分层星场
- 极淡星云背景
- 地球暗面城市灯光渐亮
- 云层缓慢漂移
- 大气边缘光增强
- 少量近景微尘

### Chapter 2：掠过昼夜（2.2～4.5 秒）

目标：建立真正的空间穿越感。

新增：

- 太阳边缘光增强
- 卫星 / 探测器从前景掠过
- 第一颗远中景流星
- 近景微尘产生明显视差

### Chapter 3：穿越内行星（4.5～7.2 秒）

目标：从单体天体过渡到太阳系结构。

新增：

- 水星 / 金星 / 火星经过感增强
- 第一组内轨逐段点亮
- 少量碎石进入画面
- 深空结构继续缓慢变化

### Chapter 4：太阳系展开（7.2～9.6 秒）

目标：形成自动镜头的视觉高潮。

新增：

- 局部小行星带穿越
- 多条轨道完整展开
- 太阳光晕 / 耀斑短暂高潮
- 第二颗更远、更弱的流星
- 镜头逐步拉到太阳系全景

### Chapter 5：抵达知识宇宙（9.6～12 秒）

目标：从太阳系收束为博客身份。

新增：

- 前景干扰逐渐减少
- 四个正式分类形成知识星群
- 4～6 个长期主题词作为远处信号出现
- 最终标题与操作按钮保持视觉主导

节奏原则：

> 前 80% 逐渐丰富，最后 20% 主动收干净。

## 6. 优先级

### P0：第一轮必须完成

1. 分层星场
2. 星云 / 宇宙尘埃层
3. 近景漂浮粒子
4. 低频流星
5. 卫星 / 探测器掠过
6. 轨道觉醒动画
7. 博客分类星群

### P1：第一轮验收后决定

1. 小行星带局部穿越
2. 太阳活动事件
3. 长期主题信号
4. 探索状态轻反馈增强

### 暂不做

- 行星点击详情
- 星球与文章绑定
- 复杂 HUD
- 大量漂浮文字
- 重型粒子系统
- 物理引擎
- 将开屏扩展成小游戏

## 7. 移动端原则

移动端必须保持视觉完整，但允许降低内容密度。

保留：

- 星场
- 星云
- 少量近景粒子
- 卫星
- 至少一次流星
- 轨道动画
- 分类星群

降低：

- 小行星数量约 50%
- 近景粒子数量约 50%
- 星云层数可从 3 层降到 2 层
- 不增加额外高成本 Bloom
- 不使用体积雾和大量实时阴影

## 8. 产品验收标准

完成后从真实用户视角检查：

1. 第一眼是否还会觉得“太空里太空”。
2. 自动镜头是否每 2～3 秒都有一次明显变化。
3. 新元素是否抢走太阳、地球和标题的注意力。
4. 页面是否出现“粒子特效 Demo”感。
5. 最终阶段是否能明显感受到“个人知识宇宙”。
6. 移动端是否仍然清楚、流畅。
7. “进入博客”是否仍然是最终落版最明确的动作。

如果第 3、4、7 任意一项出现明显问题，应优先删除或弱化元素，而不是继续堆叠参数。

- 分层星场
- 星云 / 宇宙尘埃层
- 近景漂浮微尘
- 两次固定低频流星事件
- 卫星 / 探测器近景掠过
- 轨道逐条觉醒与展开
- 教程 / 实践 / 生活 / 视觉实验室四个博客分类星群

P1 暂未执行，继续保留为下一轮审查项：

- 局部小行星带进一步增强
- 太阳活动高潮事件
- 长期主题信号
- 自由探索状态的额外轻反馈

本轮仍保持原有 12 秒时长、自动镜头、自由探索和博客主入口关系，不增加新的内容导航、HUD 或重型交互系统。
