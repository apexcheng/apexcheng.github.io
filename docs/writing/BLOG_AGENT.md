# 博客写作规则

本文件负责文章叙述、事实与示例、frontmatter 填写、分类应用和完稿检查。目录、公开状态默认值、索引更新及按需读取入口以 `AGENTS.md` 为准；视觉设计以 `docs/ARTICLE_VISUAL_SYSTEM.md` 为准。

视觉表达是本站的首要写作方向。文字保持专业、直接和准确，不需要刻意强化个人博客口吻。

## 内容原则

1. 不虚构作者经历、项目结果、数据或第一人称判断；为教学构造的示例须明确标注。
2. 作者提供的事实、Agent 推断和外部资料要能区分；不确定内容明确标注。
3. 保留真实场景、失败、取舍和边界，避免正确但空泛的总结。
4. 默认专业但通俗：优先使用日常语言、具体对象和真实场景解释概念；必要术语首次出现时，用目标读者能理解的话说明。

## 读者视角写作

正式文章默认面向最终读者，而不是面向作者、Agent 或当前协作会话。文章结构和表达应从“读者需要知道什么、按什么顺序最容易理解”出发，而不是复述 Agent 的分析、执行和决策过程。

- 不把 Prompt、任务拆解、需求确认、内部推理、修改过程或 Agent 自我说明写进正文，除非这些内容本身就是文章主题。
- 避免保留“我来分析”“本次任务”“根据用户要求”“Agent 需要”等描述协作过程的表达。
- 需要解释方案取舍时，直接说明问题、原因、选择、结果和边界，不描述 Agent 是怎样思考出来的。
- 第一人称只用于作者真实经历、判断和实践，不由 Agent 代替作者制造经历或观点。
- 判断一段内容是否应该保留时，问：**如果读者完全不知道这篇文章是由 AI 协助整理的，这段内容是否仍然有价值？** 如果没有，应删除或改写。

## Frontmatter

新文章从 `templates/post.mdx` 开始，字段类型以 `src/content.config.ts` 为准；下表规定填写约定。

| 字段 | 规则 |
| --- | --- |
| `title`、`description` | 必填，直接说明主题和价值 |
| `date` | 使用 `YYYY-MM-DDTHH:mm:ss+08:00` |
| `updated` | 可选，存在时使用相同格式 |
| `category` | 只能使用固定分类 |
| `tags` | 使用具体主题词 |
| `minutes` | 使用合理的阅读时间整数 |
| `featured` | 默认 `false` |
| `pinned` | 默认 `false`；设为 `true` 时在文章列表页置顶 |
| `archived` | 默认 `false`；设为 `true` 时保留原文章 URL，但退出默认列表、首页、系列阅读路线、站内搜索、RSS 等推荐入口；文章列表可勾选「包含已归档」查看 |
| `series`、`seriesOrder` | 可选；进入系列时两个字段同时填写，顺序使用正整数 |
| `draft`、`private` | 新文章默认值遵循 `AGENTS.md`；不因普通内容编辑改变已有文章的公开状态 |

`private: true` 只表示不进入公开页面和索引，不是密码保护。

`archived: true` 不是删除或私密保护；知道原链接的读者仍可访问，搜索引擎也可能通过外部链接找到文章。永久删除文章需单独处理源码及已有引用，不提供网页删除按钮。

草稿和私密文章在公开前不要求进入内容索引。

## 分类

| 分类 | 使用场景 |
| --- | --- |
| `生活` | 健康、消费、工作感受和日常观察 |
| `实践` | 项目、工具改造、踩坑、工作流和实际案例 |
| `教程` | 系统教学、系列内容和操作手册 |
| `视觉实验室` | 组件、交互、图表和文章展示方式 Demo |

新文章默认使用 `实践`；生活经验用 `生活`；系统教学用 `教程`。

## 工作方式

### 小范围修改

改字、事实修正、链接、frontmatter 和局部小改直接执行：

- 只读目标文章和必要上下文。
- 不重新规划全文。
- 不读取视觉模式库或 Demo。

### 新文章或结构性重写

按 `AGENTS.md` 的路由读取视觉规则；仅在涉及 MDX 自定义实现时读取 MDX 指南。叙述顺序按下节组织，文字和视觉共同推进解释。

### 解释性文章的递进论述

从目标读者已有的知识出发，识别理解主题所缺的前提，再围绕读者问题安排顺序。可以先给简短结论或例子吸引阅读，但后续解释不能跳过必要前提。涉及指标、模型或预测时，按需交代以下内容：

1. **场景与问题**：交代要解决的问题，以及必要的对象、时间和使用场景。
2. **来源与口径**：关键事实和数字给出可定位的来源或作者提供的依据；定义、变量和计算规则在使用前说明。涉及指标时，交代统计对象、周期、单位及筛选范围；比例还需说明分子和分母。来源无法核实时明确标注，不补造出处。
3. **推导与应用**：展示事实怎样经过计算、筛选或判断得到结果；复杂过程用少量中间状态衔接，不只列公式和结论。
4. **结果与边界**：解释结果能支持什么判断；区分原始事实、据实计算的指标、暂估与未来预测。预测需说明依据、假设和时间范围；缺失值不能当作零，缺少预测依据时不能把历史指标直接当作未来结果。限制应在影响理解或使用的位置出现，不只留到文末。

以上是检查理解前提的线索，不是固定的四段式模板；不涉及数据或预测的文章无需补齐这些项目。观点文章可从反例展开，教程可先给可运行示例，以读者无需自行补齐隐含前提为准。

**例子的自洽性**：同一示例的初始值、过程和结论必须一致，比例可复算，记录所属周期与观察时间可区分；改变假设时明确指出。教学示例说明推导，不据此宣称真实效果或预测准确率。使用生活类比时，说明与原模型的对应关系及关键差异。

参考旧文、组件、模式或 Demo 时，按 `AGENTS.md` 的路由读取，不为完成写作默认遍历资料。

## 静态文件

下载文件放在 `public/files/`，文章使用 `/files/` 链接。这里是公开文件目录，不能放私密资料、账号、token 或其他敏感文件；private 文章不等于 private 文件。

## 完稿读者体验审查

新增文章、结构性重写或较大文章改造完成后，必须以“第一次看到这篇文章的目标读者”身份重新通读全文。局部修正只复核受影响内容；是否需要浏览页面，按下节的页面检查范围执行。

### 内容理解

- 阅读顺序是否自然，关键结论是否在合适的位置出现。
- 新概念、术语、变量、公式和业务口径是否在第一次出现时能被理解。
- 是否存在逻辑跳跃、突然出现的数字或前提、重复解释和信息过载。
- 示例是否能独立跑通，读者能否从输入一路看懂到结果。
- 主线和扩展内容是否分层清楚，重点是否足够突出。

涉及视觉表达时，按 `docs/ARTICLE_VISUAL_SYSTEM.md` 的“视觉审查”核对，不另设一套视觉清单。

## 最小发布检查

文章创建或编辑完成后：

1. frontmatter 符合字段约定，公开状态符合用户要求和 `AGENTS.md`。
2. 没有模板占位词和明显敏感信息。
3. 运行当前环境中可用的相关测试或构建；不可运行时直接说明。

只有新增复杂视觉结构、修改布局或文章专属 CSS 时，才需浏览桌面端和移动端页面，核对关系表达、可读性与相关交互；发现问题后修正并复查。无法浏览时报告未验范围，不把静态阅读或构建通过视为页面验收通过。仅修改规则文档时，验证按 `docs/DEV_RULES.md` 执行。
