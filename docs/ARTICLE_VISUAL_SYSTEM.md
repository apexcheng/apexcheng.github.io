# 文章视觉系统

本文件负责正式文章的信息视觉化、阅读排版与视觉审查。内容与事实要求、完稿及发布检查以 `docs/writing/BLOG_AGENT.md` 为准；具体表达模式按需查 `docs/MDX_PATTERN_LIBRARY.md`。

## 核心原则

```text
先判断信息关系，再选择网页表达，让文字与视觉共同讲清内容。
```

1. 优先设计能降低理解成本的视觉结构；若图解并未比正文、列表或表格更清楚地表达关系，保留简洁表达。
2. 文字建立情境、提供论据并解释含义，图解呈现关系与变化。必要的图注、文字摘要和替代说明不算无效重复。
3. 不机械复制旧文章、Demo、固定卡片数量或固定章节骨架。
4. 文章可以组合正文、HTML、MDX 组件、表格、代码和 Mermaid；选择标准是理解成本。
5. 小范围文章修改不触发全文视觉重构。

## 三个轻量判断

新文章或结构性重写前只判断：

1. **核心信息关系**：流程、判断、对比、分层、风险、数据、行动或结论。
2. **整页视觉概念**：例如教学手册、系统地图、操作控制台、决策地图或数据故事。
3. **移动端转换**：横向关系如何纵向化，哪些区域允许局部滚动。

不要求把判断输出成长篇方案；能指导实现即可。

## 文章形态

以下是方向，不是模板：

| 形态 | 适合内容 | 重点 |
| --- | --- | --- |
| 图解手册 | 教程、规则、原理、操作说明 | 独立讲清概念、过程、案例和边界 |
| 视觉叙事 | 项目实践、工作流、系统改造、复盘 | 让输入、判断、执行和结果形成连续阅读路径 |
| 设计化文章 | 观点、生活、职场和经验 | 保留文字节奏，用少量专属视觉结构强化判断 |

可以混合使用，不要求先给文章贴固定类型标签。

## 视觉叙事与专业参考

专业信息图、流程图、演示稿、系统架构图和数据新闻可提供信息组织方式。复杂文章可以用连续图解推进解释，也可以交替使用正文与图解；不要求每章配图，也不把网页切成彼此孤立的幻灯片或重复卡片。

1. **明确阅读任务**：每个关键视觉模块回答一个清楚的问题；用标题、图注或标注提示读者看哪里、能得出什么。
2. **选择视觉语法**：流程表达顺序与分支，架构表达层级和连接，数据图表服务比较、分布或变化等任务，推演呈现必要的输入、中间结果和输出。多层架构图、注释型信息图或交互演示都可使用，复杂度以解释真实关系所需为限。
3. **复杂关系分层呈现**：先展示全貌，再突出局部或逐步揭示；需要回看时保留完整静态图或文字路径。复杂度应来自真实信息关系，不是更多装饰、连线和动画。
4. **保持网页原生优势**：有价值时使用局部强调、前后状态切换、分步解释和轻交互；阅读主线不得依赖动画、悬停或复杂操作才能理解。避免为了“高级感”引入重型运行时或无关特效。

只有现有表达难以讲清内容时，才按需查阅外部范例；不设每篇查询或范例数量要求。可从模式库的“专业视觉参考”选取起点，重点学习分组、主次、标注、阅读顺序和移动端转换；引用具体观点或素材时标明出处，使用素材须遵守其授权。

## 图解与数据的准确表达

1. 节点、分组和箭头含义明确；调用、数据流、时间顺序和因果关系不能混为一种连线，相关性不能画成已证实的因果。
2. 图表中保留理解所需的对象、周期、单位、图例和口径提示，与正文一致；来源及计算要求遵循写作规则。坐标、比例、面积和时间间隔应忠实表达数据，截断坐标或归一化处理须明确标示。
3. 同图呈现事实、指标、暂估或预测时，用文字标签、分界或线型区分，并指向对应的依据与假设，不能用连续曲线或统一样式暗示它们具有相同确定性。

## 视觉语言

1. 同一篇文章保持颜色、标签、边框和层级语义稳定。
2. 标签、图标、编号和颜色必须表达信息，不作为装饰。
3. 卡片只承载适合卡片的信息，不把长段正文切碎后强行装入。
4. 代码和命令保持可复制文本。
5. 概念模式名称不代表项目中存在同名组件；真实 API 以 `docs/MDX_COMPONENTS.md` 为准。

## 字体与阅读排版

1. 文章沿用全站基础字体：中文 **Noto Sans SC**、英文与数字 **Inter**、代码 **JetBrains Mono**。字体定义与加载入口以 `public/fonts/typography.css`、`src/styles/global.css` 为准。
2. 阅读主题切换只调整配色等视觉属性，不更换普通标题或正文字体；当前可用主题以 `docs/DEV_RULES.md` 的站点交互约定为准。
3. 普通文章正文桌面端以 **17px / 1.8 行高**、移动端以 **16px** 为基准；长段落阅读宽度宜控制在 **800px 以内**。图表、表格、代码和复杂视觉块可按需要拓宽。
4. 标题、导航和标签优先采用清晰的字号与 **400/500/600/700** 字重层级；中文标题避免明显的负字距，不用压缩字距制造“高级感”。
5. 文章专属设计可以使用不同的封面字体、视觉数字或局部字号，但应限定在专属 class / 组件中，不随意覆盖全站基础正文与文章标题。
6. 字体资源本地托管，中文使用按字符范围分片；调整字体时同时关注加载体积、`font-display`、回退字体与布局跳动，避免因字体美化牺牲阅读速度。
7. 代码块使用统一的 `--mono-font`：英文优先 JetBrains Mono，中文明确回退 Noto Sans SC；内部 `code` 元素继承代码块字体，常规字号 **14px / 1.75 行高**。纯文本流程图保留空格、换行和水平滚动；复杂多列对齐图应使用 Mermaid 或 HTML，不能假设中英文字符占用完全相同的宽度。目标环境包含 Windows 时，重点检查中英文混排。

## 响应式与可访问性

1. 横向流程和多列布局在移动端改为纵向，保留顺序、分支和对应关系；长表格和确需保留空间关系的复杂图可局部横向滚动，并提供可读的概览或文字路径。
2. 整页不能横向溢出，不通过缩小正文和教学文字解决布局问题。
3. 图片提供替代文本，交互元素可通过键盘使用，焦点状态可见。
4. 颜色不能是唯一的信息提示，文本与背景保持清晰对比。
5. 动画尊重 `prefers-reduced-motion`；复杂图表保留文字说明。
6. 视觉块内部不要重复使用会污染文章目录的 `H2`。

## 视觉审查

检查是否帮助读者更快、更准确地理解，而不只检查美观或溢出：

- 视觉关系与事实一致，重点对应正文问题；无需逐字重读卡片才能找到结论。
- 涉及推导时，能沿必要的输入、处理和中间状态看懂结果；简单结论不强行补全流程。
- 桌面与移动端都能读清标注、追踪关系并完成相关交互，不能只做到“不溢出”。

没有明确解释作用的视觉块应简化、重构或删除。全文通读、页面检查的触发范围和构建要求统一见 `docs/writing/BLOG_AGENT.md`。
