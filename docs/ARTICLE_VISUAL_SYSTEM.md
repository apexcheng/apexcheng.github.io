# 文章视觉系统

本文件是正式文章的视觉设计总规则。目标是让文章成为可滚动阅读的网页作品，而不是给长正文补装饰。

## 核心原则

```text
先判断信息关系，再设计网页表达，最后编写正文。
```

1. 视觉结构承担流程、对比、分层、判断和结果等主要关系。
2. 正文补充事实、背景、经验和边界，不重复视觉块已经表达的内容。
3. 不机械复制旧文章、Demo、固定卡片数量或固定章节骨架。
4. 文章可以组合正文、HTML、MDX 组件、表格、代码和 Mermaid；选择标准是理解成本。
5. 教程、流程、规则和系统文章优先使用完整视觉章节，但不要求每个 `H2` 使用相同结构。
6. 小范围文章修改不触发全文视觉重构。

## 三个轻量判断

新文章或结构性重写前只判断：

1. **核心信息关系**：流程、判断、对比、分层、风险、数据、行动或结论。
2. **整页视觉概念**：例如教学手册、系统地图、操作控制台、决策地图或数据故事。
3. **移动端转换**：横向关系如何纵向化，哪些区域允许局部滚动。

不要求把判断输出成长篇方案；能指导实现即可。

## 文章形态

以下是方向，不是模板：

| 形态 | 适合内容 | 重点 |
| --- | --- | --- |
| 图解手册 | 教程、规则、原理、操作说明 | 独立讲清概念、过程、案例和边界 |
| 视觉叙事 | 项目实践、工作流、系统改造、复盘 | 让输入、判断、执行和结果形成连续阅读路径 |
| 设计化文章 | 观点、生活、职场和经验 | 保留文字节奏，用少量专属视觉结构强化判断 |

可以混合使用，不要求先给文章贴固定类型标签。

## 内容关系选型

| 内容关系 | 优先表达 |
| --- | --- |
| 少量关键结论 | 结论面板或短强调块 |
| 并列模块 | 宫格、能力矩阵或分栏 |
| 数字和状态 | 指标卡或报告面板 |
| 线性步骤 | 流程轨道或步骤卡 |
| 条件分支 | 决策树或 Mermaid |
| 方案取舍 | 对比面板或表格 |
| 系统层级 | 架构板、文件地图或数据流 |
| 案例过程 | 时间线、问题链路或案例拆解 |
| 公式和数据 | 参数映射板、示例表和结果区 |

公式运行、数据处理、新旧方案对比和多阶段业务逻辑，优先参考 `src/content/posts/visual-lab/runtime-mechanism-visual-pattern.mdx`：先展示输入与处理过程，再让关键中间结果、适用边界和最终判断依次可见。

模式细节只在需要时参考 `docs/MDX_PATTERN_LIBRARY.md`。

## 视觉语言

1. 同一篇文章保持颜色、标签、边框和层级语义稳定。
2. 标签、图标、编号和颜色必须表达信息，不作为装饰。
3. 卡片只承载适合卡片的信息，不把长段正文切碎后强行装入。
4. 代码和命令保持可复制文本。
5. 概念模式名称不代表项目中存在同名组件；真实 API 以 `docs/MDX_COMPONENTS.md` 为准。

## 响应式与可访问性

1. 横向流程和多列布局在移动端改为纵向；长表格可以局部横向滚动。
2. 整页不能横向溢出，不通过缩小正文和教学文字解决布局问题。
3. 图片提供替代文本，交互元素可通过键盘使用，焦点状态可见。
4. 颜色不能是唯一的信息提示，文本与背景保持清晰对比。
5. 动画尊重 `prefers-reduced-motion`；复杂图表保留文字说明。
6. 视觉块内部不要重复使用会污染文章目录的 `H2`。

## 验证边界

普通文字和 frontmatter 修改不需要视觉检查。只有新增复杂视觉结构、修改布局或文章专属 CSS 时，才检查一次桌面端和移动端页面，并运行当前环境中可用的构建。
