# 文章视觉参考

本文件是可选的设计参考，不是统一视觉规范、文章模板或验收清单。每篇文章都可以拥有自己的视觉语言，也可以完全不使用复杂视觉设计。

## 设计自由

- 可以根据主题采用杂志、报刊、技术手册、数据故事、演示稿、产品页面、互动叙事、极简长文或其他视觉形式。
- 可以自由选择字体、字号、宽度、行高、颜色、布局、动效、组件和页面结构，不必沿用全站文章的默认样式。
- 可以创建文章专属组件、样式和交互；真实技术实现仍遵守项目工程规则。
- 可以参考旧文章、外部作品和视觉实验室，也可以完全另起炉灶。
- 不需要为了使用图表、卡片、流程图或交互而使用它们；也不因为某种形式以前没出现过就拒绝尝试。

## 基本质量底线

设计需要满足实际阅读任务：内容可理解，信息关系不误导，文字和交互可用。桌面与移动端都应有合理体验；复杂视觉可以采用适合自己的响应式处理方式，不要求所有布局都变成相同的纵向卡片。

图表、流程图和示意图应忠实表达数据与关系；颜色不应成为唯一的信息载体。重要内容不应只能通过悬停、动画或复杂操作才能获取。交互应考虑键盘使用和清晰的焦点状态，动画尊重 `prefers-reduced-motion`。

这些是结果要求，不限定实现手段。遇到特殊作品形式时，可以为其设计合适的阅读和交互方式。

## 参考方向

以下只是可选灵感，不是固定分类或组件映射：

- 图解手册、连续信息图、滚动叙事和数据新闻
- 杂志式文章、编辑设计、海报式章节和视觉故事
- 系统地图、架构图、时序图、决策图和流程演示
- 数据仪表盘、交互教学、模拟器和可探索的案例
- 极简排版、长篇叙事、摄影与文字组合

## 评估设计

判断设计是否成立，重点看它是否准确传达内容、是否适合主题、是否帮助读者理解，以及实际阅读和交互是否顺畅。不要因为它不符合已有组件、旧文章风格或某套设计流程而要求改回统一模板。
