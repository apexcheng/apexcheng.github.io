# MDX 视觉模式库

只在文章存在复杂信息关系、现有视觉总则不足以完成设计时读取本文件。模式用于选择表达，不是固定模板。

## 快速选择

| 内容关系 | 模式 | 避免 |
| --- | --- | --- |
| 文章级判断 | 结论面板 | 把普通引言装进卡片 |
| 3 到 4 个并列角度 | Bento / 信息宫格 | 混入流程或长段落 |
| 少量数字和状态 | 指标看板 | 使用没有口径的装饰数字 |
| 两种方案取舍 | 对比面板 | 对比项很多却不用表格 |
| 线性演进 | 时间线 / `DecisionFlow` | 没有顺序却强行编号 |
| 因果排查 | 问题链路 | 一张图塞入全部细节 |
| 条件选择 | 决策树 / Mermaid | 条件模糊或分支过深 |
| 具体实践 | 案例拆解板 | 没有动作和结果 |
| 发布或操作确认 | 检查清单块 | 把完整手册压成清单 |
| 公式与数据关系 | 参数映射板 | 只解释参数名、不展示结果 |

能用普通 Markdown 清楚表达时，不使用模式。

## 完整视觉章节

教程、原理、规则、流程和系统说明可以把一个主要问题设计成完整视觉章节。章节按内容选择必要部分：

```text
问题或定义
关系或流程
核心解析
案例、数据或结果
错误、边界或结论
```

不要求每章包含全部部分，也不要求所有章节使用同一布局。共享颜色和层级语义即可。

## 高信息密度模式

### 功能矩阵

用于并列能力、模块地图和系统职责。每项保留一个标题、一句说明和少量标签；有先后顺序时改用流程。

### 报告面板

用于验收结果、风险分层和稳定性复盘。顶部只放少量真实指标，下方按风险或保障层组织；没有指标和层级时不用。

### 决策地图

用于工具选型和需求分流。保留 3 到 4 个能明确回答的判断，每条路径落到具体动作；线性步骤不用决策树。

这三种模式的实际效果可按需参考 `src/content/posts/visual-lab/screenshot-mdx-replica-demo.mdx`，不得直接复用其中的硬编码组件和文案。

## 公式参数映射板

适用于 Excel、WPS、SQL、正则表达式、查询条件和数据筛选教程。

核心关系：

```text
原始数据
  ↓
公式参数对应的数据区域
  ↓
实际命中或定位过程
  ↓
计算过程和最终结果
```

规则：

1. 使用少量真实数据样本，不只展示抽象列名。
2. 参数与对应数据区域使用相同颜色。
3. 区分完整检查范围和实际命中记录。
4. 必须展示最终结果；必要时展示中间计算。
5. 错误案例使用“公式 → 实际结果 → 原因 → 正确写法”。
6. 箭头尽量短且不交叉，移动端改为纵向。
7. 一个颜色只承担一种稳定语义。

教学文字底线：

| 内容 | 建议字号 |
| --- | --- |
| 编号和小标签 | 11-12px |
| 参数补充和表头说明 | 12-13px |
| 步骤和卡片正文 | 13-14px |
| 表格正文 | 14-15px |
| 公式 | 15-17px |
| 最终结果 | 18px 以上 |

表格或公式放不下时允许局部横向滚动，不缩小正文。

### 多函数教程

逐个教授多个函数时，每个函数使用独立案例板，分别展示数据、公式、参数映射、命中过程和结果。同一函数家族复用稳定的视觉关系，不因函数名不同重新设计整套语言。

常用映射：

| 关系 | 适用函数 |
| --- | --- |
| 条件命中与汇总 | `COUNTIF(S)`、`SUMIF(S)`、`AVERAGEIF` |
| 文本切片与长度 | `LEFT`、`RIGHT`、`MID`、`LEN` |
| 文本清洗与替换 | `TRIM`、`SUBSTITUTE` |
| 多值拼接 | `TEXTJOIN` |
| 文字位置 | `FIND`、`SEARCH` |
| 查找行映射 | `VLOOKUP`、`XLOOKUP` |
| 位置和坐标 | `INDEX`、`MATCH`、`XMATCH` |
