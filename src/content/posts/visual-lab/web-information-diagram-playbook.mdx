网页不只是把正文装进漂亮的容器。图纸、流程、说明书、地图、交互模型、数据新闻都在解决同一个问题：**让读者看见对象之间的关系，而不是逐句在脑中拼接关系。**

这是一份可直接比较展示效果的视觉实验：用「ChatGPT 通过 MCP 访问本地工具」这个共同题材，尝试六种不同的信息表达。图中地址、链路、测试状态如无特别注明均是**教学示意**，不是实时生产监控数据。

想了解完整的实际连接步骤，可以对照 [《让 ChatGPT 连接本地 MCP：三种接入方案与完整实践》](/articles/chatgpt-local-mcp-three-access-methods/)；这里专门研究「信息怎样被画清楚」。

## 哪种视觉适合哪类内容？

| 主要问题 | 更合适的表达 | 不宜这样用 |
| --- | --- | --- |
| 有哪些层和路径？ | 系统地图 / 拓扑图 | 不区分数据、控制和部署关系 |
| 谁在哪一步负责什么？ | 泳道流程 | 参与者与时间阶段混为一轴 |
| 部件在哪、边界在哪？ | 注释型图纸 | 标注线被误读为连接线 |
| 选择哪套方案？ | 决策树 | 把所有背景文字塞进节点 |
| 需要先易后难地理解？ | 渐进展示 / 折叠细节 | 把核心结论藏在交互之后 |
| 多系统如何往返？ | 时序图 | 用虚构耗时误导读者 |
| 需要比较大量量化证据？ | 标注型数据图 / 交互图表 | 不写时间、单位、来源与统计口径 |

## 从哪些优秀网页和设计实践借鉴？

这次检索不局限于个人博客，也参考了数据新闻、工程架构、教学交互和数据可视化：

- [The Pudding](https://pudding.cool/)：用**滚动叙事和内容驱动的图形变化**解释复杂议题；其 [Resources](https://pudding.cool/resources/) 提供制作方法。
- [Explorable Explanations](https://explorabl.es/)：读者可操作参数、观察结果，适合把抽象逻辑变成小实验；不一定需要大型交互框架。
- [Observable Plot 示例集](https://observablehq.com/@observablehq/-/collection/plot-examples)：适合密度图、分布、比较、趋势与注释型数据图，强调数据关系而不是装饰。
- [Ilograph](https://www.ilograph.com/)：适合分层架构、多视角系统关系与复杂系统的逐层展开。
- [Mermaid 文档](https://mermaid.js.org/)：适合维护成本低的流程图、时序图、状态图；不追求替代所有自由布局工程图。
- [Shorthand 互动信息图案例](https://shorthand.com/the-craft/interactive-infographics/index.html)：可参考注释、视觉场景与滚动讲解的协调方式。

<Callout title="实验结论">
  真正值得复用的不是配色、阴影或动画，而是六种信息关系的表达规则：**对象与连接、角色与阶段、结构与注释、条件与选择、主线与细节、消息与时间**。正式文章只选能提高理解效率的模式，不应为每章强行增加复杂图解。
</Callout>
