职场里有一句很有意思的隐喻：

> **人人都是农民，人人都想当地主。**

这里的“农民”和“地主”当然不是字面意义上的身份。

“农民”指主要依靠自己的时间、劳动和执行力换取收入的人；“地主”则代表掌握资源、分配权、评价权和指挥权的人。

真正值得观察的，不是一个人想不想获得更大的权力。升职、管理别人、拥有更多资源，本身都没有问题。

问题在于：**有些人刚获得一点权力，最先学会的不是承担更多责任，而是如何证明自己已经不是“农民”。**

一句话概括这种状态：

> **权力上收，责任下沉；意图属于领导，理解成本属于下属。**

## 刚拿到一点权力，就急着证明自己不是“农民”

这种变化有时候很明显。

一个人在职位比较低的时候，会抱怨领导为什么不把事情说清楚、为什么总让下面的人猜、为什么出了问题才回来追责。

但等他自己有了一点管理权限，很快开始重复同样的行为。

面对上级和平级，他会认真组织语言、确认分工、说明背景；面对比自己职位低的人，却开始觉得这些沟通成本没有必要：

> 这个你跟一下。

> 你看着处理。

> 这还要我明确说吗？

这时候真正发生变化的，不一定是沟通能力，而是他对双方关系的理解。

**他开始认为：因为自己的职位更高，所以别人应该承担更多“理解自己”的成本。**

## A、B、C：一个很小，却很典型的例子

假设 A 是 B 和 C 的领导。

A 和 B 讨论了一件事情，最后认为这件事应该交给 C 去做。

正常的管理链路其实很简单：

<div class="landlord-flow-grid">
  <section class="landlord-flow landlord-flow--good">
    <div class="landlord-flow__label">合理链路</div>
    <div class="landlord-flow__steps">
      <span>A 做决定</span><b>→</b><span>A 给 C 派任务</span><b>→</b><span>C 执行</span>
    </div>
    <p>或者 A 明确授权 B：“这件事你帮我安排 C 做。”</p>
  </section>

  <section class="landlord-flow landlord-flow--bad">
    <div class="landlord-flow__label">责任模糊链路</div>
    <div class="landlord-flow__steps">
      <span>A 和 B 聊到此事</span><b>→</b><span>无人给 C 派任务</span><b>→</b><span>A 回头追问 B</span>
    </div>
    <p>“你为什么没有让 C 做？”</p>
  </section>
</div>

后者看起来只是少做了一个“派任务”的动作，但背后的逻辑完全不同。

A 实际上默认：

> **我的想法一旦说出口，下属就应该自动补全后面的管理动作。**

于是，A 不需要明确告诉 C，也不需要明确授权 B；B 却要主动判断 A 的真实意图、判断是否应该越过自己的权限去安排 C，最后还要为事情没有发生承担责任。

这已经不只是沟通疏忽，而是一种非常方便的责任结构。

## “你应该懂我的意思”，给管理者留下了最大的解释空间

这种方式为什么容易出现？

因为它对掌握权力的人太方便了。

<div class="landlord-outcomes">
  <div>
    <span>事情做成了</span>
    <strong>“这是我安排的。”</strong>
  </div>
  <div>
    <span>事情没做</span>
    <strong>“你为什么没理解？”</strong>
  </div>
  <div>
    <span>事情做错了</span>
    <strong>“我又没让你这么做。”</strong>
  </div>

领导只负责表达模糊的意图。

下面的人却要负责理解意图、补全流程、判断权限、安排执行、决定优先级，最后还要承担结果。

**权力是明确的，责任却保持模糊。**

而责任越模糊，事后解释空间就越大。

## B 不给 C 派任务，反而可能是正常的职业边界

很多人会问：既然 B 已经知道这件事应该由 C 做，为什么不顺手告诉 C？

因为组织里还有一个很重要的东西：**权限边界。**

如果 B 并没有管理 C 的权限，那么 B 主动给 C 派任务，本身就可能形成越级指挥。

结果可能是：C 不知道这件事和原有任务谁优先；C 的正式负责人不知道任务从哪里来的；出了问题，也没人说得清究竟是谁做出的正式决定。

所以最简单的规则其实是：

<HighlightBox eyebrow="权责边界" title="谁拥有管理权，谁完成正式的任务分配">
  如果需要别人代为安排，就明确授权。领导“不必亲自执行”，不等于领导“不必把管理动作做完整”。
</HighlightBox>

要求 B 主动越过权限边界，替 A 完成 A 没有完成的管理动作，本质上是在要求下属替领导承担管理成本。

更麻烦的是，如果 B 真这么做了，未来出了问题，A 仍然可以说：“我什么时候让你给 C 派任务了？”

## 对上讲流程，对下讲“你应该懂”

这类人身上经常出现一个很有意思的反差。

<div class="landlord-contrast">
  <section>
    <span>面对上级</span>
    <h3>流程必须清楚</h3>
    <ul>
      <li>是谁负责的？</li>
      <li>有没有明确要求？</li>
      <li>什么时候安排的？</li>
      <li>有没有聊天记录？</li>
    </ul>
  </section>
  <section>
    <span>面对下属</span>
    <h3>你应该自己懂</h3>
    <ul>
      <li>这种事还要我说？</li>
      <li>你自己不会判断吗？</li>
      <li>还要我什么都安排好？</li>
      <li>为什么没有主动推进？</li>
    </ul>
  </section>
</div>

为什么会这样？

因为面对上级，他需要流程来保护自己；面对下级，他却更希望流程保持模糊。

流程越清楚，责任越清楚。

责任越模糊，权力拥有者越容易在事后选择对自己有利的解释。

## 真正的问题不是职位高，而是身份膨胀

管理者当然不应该事事亲力亲为。

真正的问题，是有人把“领导不必亲自执行”，慢慢偷换成了：

> **领导不必把事情说明白，也不必把管理过程做完整。**

这是两件完全不同的事情。

正常的管理逻辑应该是：

**我拥有决策权，所以我有责任把决定表达清楚并落实下去。**

而“地主式”的管理逻辑是：

**我拥有决策权，所以具体怎么理解、怎么落实，是下面的人应该自己想明白的。**

职位越高，掌握的信息和资源通常越多，一个错误决定造成的影响也越大。因此权力增加，本来就应该伴随更多的决策责任、任务定义责任、权限划分责任和结果责任。

不是反过来。

## 有些人不是想当地主，只是想拿到鞭子

所以我后来觉得，“人人都是农民，人人都想当地主”还可以再往前走一步。

很多人真正迷恋的，甚至不是成为一个承担经营、风险和长期结果的“地主”。

他们迷恋的是：**终于有资格指挥别人。**

刚获得一点权力，就迫不及待通过支配职位更低的人，证明自己的身份已经发生变化。

<HighlightBox eyebrow="这句话真正讽刺的地方" title="有些人不是想成为承担经营责任的地主，只是刚拿到一点鞭子，就迫不及待想证明自己已经不是农民">
  判断一个管理者，不要只看他能指挥多少人。更值得看的是：当他拥有权力以后，是否愿意承担与这份权力相匹配的责任。
</HighlightBox>

## 管理不是让别人更懂你，而是让组织少猜你

一个好的团队，不应该依赖几个特别会“领会领导精神”的人才能正常运行。

谁决定，谁执行，谁协同，谁负责最终结果——这些事情应该尽可能清楚。

因为组织效率不应该建立在猜测之上。

真正成熟的管理，不是：

> 我说一句，你们自己悟。

而是：

> **我拥有这个权力，所以我负责把这件事情说清楚。**

职位本身并不值得炫耀。

真正能体现管理能力的，从来不是一个人能指挥多少人，而是他获得权力以后，能不能承担更多责任，而不是把责任继续向下推。
