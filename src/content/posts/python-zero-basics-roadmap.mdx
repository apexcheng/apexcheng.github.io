Python 代码不是一次性把整页“算完”。默认情况下，它从上到下走到一行、完成这一行，再去下一行。运行时有些变化能在终端里看到，更多变化却藏在程序内部：表达式先得到结果、变量记住结果、条件得到 `True` 或 `False`，最后才可能产生输出。

这一章不要求先记语法。先把代码当成一条可以逐站观察的轨道，学会回答四个问题：**现在运行哪一行？这一行拿到什么？内部状态怎样改变？有没有产生输出？**

## 一行赋值，不是把等号两边同时连起来

先看一行可以直接运行的代码：

```python
paid_total = 129.0 + 199.0
```

这里的 `=` 不是数学题里的“左右相等”。Python 会先处理右侧，再让左侧的名字记住结果。

<figure class="py-runtime-lesson py-runtime-assignment" aria-labelledby="assignment-caption">
  <figcaption id="assignment-caption">
    <span class="py-runtime-kicker">单行赋值观察台</span>
    <strong><code>paid_total = 129.0 + 199.0</code></strong>
  </figcaption>
  <ol class="py-runtime-flow">
    <li>
      <span class="py-runtime-label">输入 · 01</span>
      <strong>读取右侧表达式</strong>
      <code>129.0 + 199.0</code>
      <small>此时还没有名为 paid_total 的变量。</small>
    </li>
    <li>
      <span class="py-runtime-label">当前行 · 02</span>
      <strong>先计算右侧</strong>
      <code>129.0 + 199.0 → 328.0</code>
      <small>表达式先产生一个值。</small>
    </li>
    <li>
      <span class="py-runtime-label">之后 · 03</span>
      <strong>名字绑定到结果</strong>
      <div class="py-runtime-binding"><code>paid_total</code><span aria-hidden="true">→</span><b>328.0</b></div>
      <small>后面的代码可以通过名字取回这个值。</small>
    </li>
  </ol>
  <div class="py-runtime-state-strip">
    <span><b>之前</b> paid_total 不存在</span>
    <span><b>之后</b> paid_total 记住 328.0</span>
    <span><b>输出</b> 暂无</span>
  </div>
</figure>

最后一格特意写着“输出暂无”：**变量状态改变，不等于屏幕会出现文字。** 只有代码明确调用 `print()` 等输出动作时，终端才会显示内容。

```python
paid_total = 129.0 + 199.0
print(paid_total)
```

这两行运行后，变量仍然保存 `328.0`，终端另外显示：

```text
328.0
```

到这里，可以先把几个词对应起来：

| 看到的东西 | 在这段代码里是什么 | 它负责什么 |
| --- | --- | --- |
| 代码行 | `paid_total = 129.0 + 199.0` | 告诉 Python 当前要做的事 |
| 表达式 | `129.0 + 199.0` | 计算并产生值 `328.0` |
| 变量状态 | `paid_total → 328.0` | 让后续代码能通过名字取得值 |
| 输出 | 终端里的 `328.0` | 把结果显示给运行代码的人 |

## 8 行订单脚本怎样从上到下运行

现在看一段完整但很短的订单脚本。先复制运行，不用急着解释每个符号：

```python
orders = [
    {"order_no": "A001", "amount": 129.0, "status": "已支付"},
    {"order_no": "A002", "amount": 88.0, "status": "已退款"},
]

for order in orders:
    if order["status"] == "已支付":
        print(order["order_no"], order["amount"])
```

算上空行，这正好是 8 行。空行方便人阅读，不会产生运行步骤。第 1～4 行先准备数据；第 6～8 行再逐条查看订单、判断状态，并决定是否输出。

这里最容易忽略的是：代码虽然只写了一次第 6、7 行，运行时却会为了不同订单回到它们。第 8 行也不是“排在后面就一定执行”，它只有在第 7 行得到 `True` 时才会到达。循环和判断会在后面的章节单独拆解；现在先会沿轨道读懂它们。

## 只改一个输入，哪一段轨迹会改变

学习代码最有效的方法之一，是先预测，再只改一个值。把 A002 的状态从“已退款”改成“已支付”，其他代码一字不动：

```python
orders = [
    {"order_no": "A001", "amount": 129.0, "status": "已支付"},
    {"order_no": "A002", "amount": 88.0, "status": "已支付"},
]

for order in orders:
    if order["status"] == "已支付":
        print(order["order_no"], order["amount"])
```

前半段轨迹完全相同：准备两条订单、处理 A001、输出 A001。变化直到第二次运行第 7 行时才出现。

  <figcaption id="diverge-caption">

    <strong>变化不是从头到尾发生，只从受影响的判断开始</strong>
  </figcaption>
  <div class="py-runtime-shared-path">
    <span>共同轨迹</span>
    <b>行 1～4 准备数据</b>
    <i aria-hidden="true">→</i>
    <b>行 6 取出 A002</b>
    <i aria-hidden="true">→</i>
    <b>行 7 检查 status</b>
  </div>
  <div class="py-runtime-branches">
    <section class="is-before">
      <span class="py-runtime-label">之前 · 输入“已退款”</span>
      <code>"已退款" == "已支付"</code>
      <strong>条件结果：False</strong>
      <p>跳过第 8 行</p>
      <output>输出仍只有 A001 129.0</output>
    </section>
    <section class="is-after">
      <span class="py-runtime-label">之后 · 输入“已支付”</span>

      <strong>条件结果：True</strong>
      <p>继续执行第 8 行</p>
      <output>新增输出 A002 88.0</output>

修改后的完整输出是：

```text
A001 129.0
A002 88.0
```

这就是调试代码时很重要的思路：不要只问“结果怎么变了”，而要找到**第一处产生不同结果的当前行**。这里不是第 6 行拿订单时出错，而是第 7 行的条件从 `False` 变成了 `True`，它又决定第 8 行是否执行。

## 如果输入缺少字段，脚本会停在哪里

运行轨道也能帮助定位错误。假设第二条订单没有 `status` 字段：

```python
orders = [
    {"order_no": "A001", "amount": 129.0, "status": "已支付"},
    {"order_no": "A002", "amount": 88.0},
]

for order in orders:
    if order["status"] == "已支付":
        print(order["order_no"], order["amount"])
```

第一条订单仍能正常输出。处理第二条订单时，第 7 行需要读取 `order["status"]`，但这条数据没有这个字段，因此脚本在这里停止，并显示 `KeyError: 'status'`。第 8 行不会为 A002 执行。

<div class="py-runtime-error" role="note" aria-label="缺少状态字段时的错误位置">
  <span>出错行 · 第 7 行</span>
  <code>order["status"]</code>
  <strong>输入里找不到 status → 无法完成条件求值 → 脚本停止</strong>
</div>

现在只需会找停止点，不必急着处理异常。后续“错误与调试”章节会专门解释错误怎样产生、怎样找到合适的处理方式。

## 按任务学习，而不是背语法目录

这段 8 行脚本已经包含后续课程的大部分主线：字符串和数字表示字段值，列表保存多条订单，字典保存一条订单的多个字段，判断决定是否处理，逐条执行让每条订单经过同一段代码，输出把结果展示出来。

学习每段新代码时，固定做四件事：

1. 先不运行，猜第一行输出会是什么。
2. 再运行，沿着代码行找到预测相同或不同的位置。
3. 只修改一个输入值，再观察第一处分岔点。
4. 用自己的话说出“输入、当前行、状态变化、输出”。

系列后续会用订单、SKU、库存、文件和 JSON 继续这条轨道：先看见数据，接着看见条件、循环与函数怎样让代码流动，最后把外部数据接入一份完整脚本。类与对象放在主线之后作为选修，因为很多几十行以内的自动化任务，用基础数据和函数已经足够。
