前面已经能把订单放进列表、把一条订单放进字典。接下来要让代码真正开始工作：**什么情况执行，什么情况跳过，一批数据怎么逐条处理。**

条件判断负责“决定”，循环负责“重复”。真实脚本经常把两者放在一起。

## `if`：条件成立才执行

```python
stock = 3

if stock < 5:
    print("需要补货")
```

`stock < 5` 会先计算出 `True` 或 `False`。

<Mermaid
  title="一条 if 判断的执行过程"
  chart={`flowchart LR
    A[stock = 3] --> B{stock < 5 ?}
    B -- True --> C[输出 需要补货]
    B -- False --> D[跳过 if 内代码]`}
/>

注意两个语法点：

```python
if stock < 5:
    print("需要补货")
```

- 条件后面有冒号 `:`。
- 属于 `if` 的代码要缩进。

缩进不是为了好看，而是在告诉 Python 哪些代码属于这个分支。

## `if / else`：两条路只走一条

```python
stock = 8

if stock < 5:
    print("需要补货")
else:
    print("库存正常")
```

结果：

```text
库存正常
```

一次判断里，`if` 和 `else` 不会同时执行。

## `if / elif / else`：多个状态从上往下检查

```python
stock = 0

if stock == 0:
    level = "缺货"
elif stock < 5:
    level = "库存偏低"
else:
    level = "库存正常"

print(level)
```

分支会从上往下检查，顺序非常重要。如果写成：

```python
if stock < 5:
    level = "库存偏低"
elif stock == 0:
    level = "缺货"
```

当 `stock = 0` 时，第一个条件已经成立，第二个分支永远不会执行。

`stock = 0` 时第一个条件已经成立，第二个分支不会执行。多条件判断既要看条件对不对，也要看哪个条件应该先判断。

## 多个条件：`and`、`or`、`not`

### `and`：两个条件都成立

```python
status = "已支付"
amount = 129.0

if status == "已支付" and amount > 100:
    print("进入高金额已支付订单")
```

### `or`：任意一个成立即可

```python
status = "已退款"

if status == "已退款" or status == "已关闭":
    print("订单不再继续处理")
```

### `not`：把真假反过来

```python
is_refunded = False

if not is_refunded:
    print("订单未退款")
```

复杂条件不要全部挤在一起。拆成有名字的布尔变量更容易检查：

```python
is_paid = status == "已支付"
is_large_order = amount > 100

if is_paid and is_large_order:
    print("需要处理")
```

## `in`：判断一个值是否在一组数据里

```python
status = "已退款"
closed_statuses = ["已退款", "已关闭", "已取消"]

if status in closed_statuses:
    print("订单已结束")
```

这通常比连续写很多个 `or` 更直观。

字符串也可以用 `in`：

```python
title = "K161 无线键盘"

if "键盘" in title:
    print("这是键盘类商品")
```

## `for`：把列表里的数据一条一条拿出来

```python
skus = ["K161", "K162", "K163"]

for sku in skus:
    print(sku)
```

执行时可以想成：

| 第几次 | `sku` 当前值 | 执行 `print(sku)` |
| ---: | --- | --- |
| 1 | `"K161"` | 输出 K161 |
| 2 | `"K162"` | 输出 K162 |
| 3 | `"K163"` | 输出 K163 |

`sku` 不是整个列表，它只是**当前这一轮取出来的一个元素**。

这是理解循环最关键的一点。

## 真实场景：逐条检查订单

```python
orders = [
    {"order_no": "A001", "amount": 129.0, "status": "已支付"},
    {"order_no": "A002", "amount": 88.0, "status": "已退款"},
    {"order_no": "A003", "amount": 199.0, "status": "已支付"},
]

for order in orders:
    if order["status"] == "已支付":
        print(order["order_no"], order["amount"])
```

  <figcaption id="conveyor-caption"><span>订单处理传送带</span><strong>循环负责送入订单，条件负责决定当前订单的动作</strong></figcaption>

  </ol>
</figure>

循环本身没有筛选能力，真正决定是否输出的是循环里面的 `if`。

## 在循环里累计数量

```python
orders = [
    {"status": "已支付", "amount": 129.0},
    {"status": "已退款", "amount": 88.0},
    {"status": "已支付", "amount": 199.0},
]

paid_count = 0

for order in orders:
    if order["status"] == "已支付":
        paid_count = paid_count + 1

print(paid_count)
```

计数器的状态台账：

| 阶段 | 当前订单状态 | 判断后 `paid_count` |
| --- | --- | ---: |
| 循环前 | — | 0 |
| 第 1 轮 | 已支付 | 1 |
| 第 2 轮 | 已退款 | 1 |
| 第 3 轮 | 已支付 | 2 |

这就是最基础的“计数器”。

也可以累加金额：

```python
total_amount = 0

for order in orders:
    total_amount = total_amount + order["amount"]
```

很多数据统计的底层思路都来自这种“循环 + 状态变量”。

## `continue`：当前这一条不处理，继续下一条

```python
orders = [
    {"order_no": "A001", "status": "已支付"},
    {"order_no": "A002", "status": "已退款"},
    {"order_no": "A003", "status": "已支付"},
]

for order in orders:
    if order["status"] == "已退款":
        continue

    print("处理订单", order["order_no"])
```

遇到 A002 时，执行 `continue`，本轮下面的代码不再执行，但循环会继续处理 A003。

## `break`：整个循环直接结束

```python
target_order_no = "A002"

for order in orders:
    if order["order_no"] == target_order_no:
        print("找到了", order)
        break
```

如果目标已经找到，后面的订单不需要继续检查，就可以 `break`。

<dl class="py-loop-control" aria-label="continue 和 break 的区别">
  <div><dt><code>continue</code></dt><dd><strong>跳过当前订单</strong><span>循环继续处理下一条</span></dd></div>
  <div><dt><code>break</code></dt><dd><strong>停止整个循环</strong><span>后续订单都不再检查</span></dd></div>
</dl>

  <summary><span>补充工具</span><strong><code>range()</code>、列表推导式和 <code>while</code></strong><small>先掌握订单循环，再按需展开</small></summary>

### `range()`：需要重复固定次数时

```python
for i in range(3):
    print(i)
```

输出：

```text
0
1
2
```

`range(3)` 产生的是从 `0` 到 `3` 之前的整数序列。

如果只是“对列表里的每一项做事”，不要为了拿下标硬写 `range(len(...))`。直接遍历元素通常更清楚：

```python
for order in orders:
    print(order)
```

如果确实同时需要序号，可以认识 `enumerate()`：

```python
for index, order in enumerate(orders, start=1):
    print(index, order["order_no"])
```

### 列表推导式：先看懂普通 `for`，再认识简写

现在已经理解了 `for`，再看列表推导式就不会只是背符号。

普通写法：

```python
numbers = [1, 2, 3, 4]
squares = []

for number in numbers:
    squares.append(number * number)
```

列表推导式把同一件事压成一行：

```python
numbers = [1, 2, 3, 4]
squares = [number * number for number in numbers]
```

两种写法都会得到：

```text
[1, 4, 9, 16]
```

入门阶段不需要强行把循环改成推导式。**一旦条件或处理步骤开始变复杂，普通 `for` 往往更容易读。**

### `while`：不知道循环次数，但知道什么时候停

`for` 适合处理一个已有集合；`while` 更像“只要条件还成立，就继续”。

```python
retry_count = 0

while retry_count < 3:
    print("执行第", retry_count + 1, "次")
    retry_count = retry_count + 1
```

看 `while` 时固定检查三件事：初始值 `retry_count = 0`、继续条件 `retry_count < 3`、状态变化 `retry_count = retry_count + 1`。

如果没有第三步：

```python
while retry_count < 3:
    print("一直执行")
```

条件永远不会变化，就会形成死循环。

### `for` 还是 `while`

| 场景 | 更自然的选择 |
| --- | --- |
| 遍历订单列表 | `for` |
| 遍历文件里的每一行 | `for` |
| 固定执行 3 次 | `for range(3)` |
| 失败后重试，直到成功或达到上限 | `while` |
| 等待某个状态发生变化 | `while`（真实自动化还要配合等待与超时） |

入门时优先把 `for` 用熟。很多新手为了“高级”而滥用 `while`，反而更容易写出停不下来的循环。

## 一个完整小案例：筛选并统计订单

```python
orders = [
    {"order_no": "A001", "amount": 129.0, "status": "已支付"},
    {"order_no": "A002", "amount": 88.0, "status": "已退款"},
    {"order_no": "A003", "amount": 199.0, "status": "已支付"},
    {"order_no": "A004", "amount": 59.0, "status": "已支付"},
]

paid_count = 0
paid_amount = 0

for order in orders:
    if order["status"] != "已支付":
        continue

    paid_count = paid_count + 1
    paid_amount = paid_amount + order["amount"]

print(f"已支付订单：{paid_count} 单")
print(f"已支付金额：{paid_amount}")
```

<ol class="py-processing-chain" aria-label="订单筛选与汇总过程">
  <li><span>读取</span><strong><code>for</code> 逐条取得订单</strong></li>
  <li><span>判断</span><strong>非已支付订单执行 <code>continue</code></strong></li>
  <li><span>累计</span><strong>已支付订单更新数量与金额</strong></li>
  <li><span>结果</span><strong>循环结束后统一输出统计</strong></li>
</ol>

如果你能跟着表格说清每一轮 `order`、`paid_count` 和 `paid_amount` 分别是什么值，循环就不是“背语法”，而是真的看懂了。

## 动手练习：库存补货清单

```python
products = [
    {"sku": "K161", "stock": 3, "enabled": True},
    {"sku": "K162", "stock": 8, "enabled": True},
    {"sku": "K163", "stock": 0, "enabled": False},
    {"sku": "K164", "stock": 2, "enabled": True},
]
```

目标：

1. 逐条遍历商品。
2. `enabled` 为 `False` 的商品直接跳过。
3. 库存小于 5 时输出 SKU 和库存。
4. 统计最终有几个 SKU 需要补货。

先自己写，再参考思路：

```python
restock_count = 0

for product in products:
    if not product["enabled"]:
        continue

    if product["stock"] < 5:
        print(product["sku"], product["stock"])
        restock_count = restock_count + 1

print("需要补货 SKU 数：", restock_count)
```

</Callout>
