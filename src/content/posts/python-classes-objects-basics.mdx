类适合解决一种更具体的问题：脚本里反复出现同一类对象，每个对象需要长期保存自己的状态，并且有多项行为总在操作这些状态。若只是读取 JSON、筛选订单、计算一次金额，字典加函数通常更直接。

## 先决定：字典加函数已经够用吗

一个商品只有 SKU、库存和补货判断时，下面的写法完全正确：

```python
product = {
    "sku": "K161",
    "stock": 3,
}


def need_restock(product):
    return product["stock"] < 5


def add_stock(product, quantity):
    product["stock"] += quantity


print(need_restock(product))
add_stock(product, 5)
print(product["stock"])
```

数据保存在字典里，函数从外部接收字典并操作它。对于几十行的临时脚本，这种关系一眼就能看懂。

## 用一个完整 `Product` 类贯穿本章

下面是本章唯一的主类。代码可以直接复制运行：

```python
class Product:
    def __init__(self, sku, stock):
        self.sku = sku
        self.stock = stock

    def need_restock(self):
        return self.stock < 5

    def add_stock(self, quantity):
        self.stock = self.stock + quantity


product1 = Product("K161", 3)
product2 = Product("K162", 10)

print(product1.sku, product1.stock, product1.need_restock())
print(product2.sku, product2.stock, product2.need_restock())

product1.add_stock(5)

print(product1.sku, product1.stock, product1.need_restock())
print(product2.sku, product2.stock, product2.need_restock())
```

输出：

```text
K161 3 True
K162 10 False
K161 8 False
K162 10 False
```

这段程序只需要先认识五个词：

| 词 | 本例 | 作用 |
| --- | --- | --- |
| 类 | `Product` | 定义这一类对象保存什么数据、能做什么 |
| 实例 / 对象 | `product1`、`product2` | 根据类创建出来的两个具体商品 |
| 属性 | `self.sku`、`self.stock` | 当前实例自己保存的数据 |
| 方法 | `need_restock()`、`add_stock()` | 当前实例可以执行的行为 |
| `self` | 正在初始化或调用方法的那个实例 | 让方法找到“这一个对象”的属性 |

## `Product("K161", 3)` 怎样变成一个实例

调用类时，Python 先准备一个新的 `Product` 实例，再调用 `__init__` 写入初始状态。`__init__` 的职责是初始化，不是把实例 `return` 出来。

<figure class="pyc-init" aria-labelledby="pyc-init-caption">
  <figcaption id="pyc-init-caption">
    <span class="pyc-kicker">调用类 → 准备实例 → __init__ → 写入属性 → 绑定名字</span>
    <strong>`Product("K161", 3)` 的初始化轨迹</strong>
  </figcaption>
  <ol>
    <li>
      <span>01 · 调用位置</span>
      <code>product1 = Product("K161", 3)</code>
      <p>请求创建一个新的 Product 实例。</p>
    </li>
    <li>
      <span>02 · 新实例</span>
      <code>self → 新的 Product 对象</code>
      <p>Python 准备空实例，并把它作为 self 交给初始化方法。</p>
    </li>
    <li>
      <span>03 · 参数进入</span>
      <code>sku → "K161"</code>
      <code>stock → 3</code>
      <p>调用中的两个实参进入 __init__ 的参数名。</p>
    </li>
    <li>
      <span>04 · 写入属性</span>
      <code>self.sku = sku</code>
      <code>self.stock = stock</code>
      <p>右边读取参数值，左边把值保存到当前实例。</p>
    </li>
    <li>
      <span>05 · 实例完成</span>
      <code>product1 → Product 实例</code>
      <code>sku: "K161" · stock: 3</code>
      <p>初始化结束，调用表达式得到实例并绑定给 product1。</p>
    </li>
  </ol>
</figure>

最容易混淆的是：

```python
self.stock = stock
```

- 右边的 `stock` 是这次调用传进 `__init__` 的参数，当前值为 `3`。
- 左边的 `self.stock` 是新实例自己的属性，以后可以通过 `product1.stock` 读取。

调用 `Product("K161", 3)` 时，不需要手工传 `self`。Python 自动让 `self` 指向当前正在初始化的新实例。

## 两个实例为什么能保存独立状态

再次调用 `Product("K162", 10)` 时，Python 会准备另一个新实例。两个对象都按照 `Product` 的定义拥有 `sku` 和 `stock`，但属性值各自保存在自己的实例中。

现在只调用：

```python
product1.add_stock(5)
```

调用方法时，Python 自动让 `self` 指向点号左边的 `product1`，并让参数 `quantity` 得到 `5`。

<figure class="pyc-state" aria-labelledby="pyc-state-caption">
  <figcaption id="pyc-state-caption">
    <span class="pyc-kicker">之前 → 当前方法 → 之后</span>
    <strong>product1 改变，product2 没有参与这次调用</strong>
  </figcaption>
  <div class="pyc-state__track">
    <section>
      <span>01 · 调用之前</span>
      <div class="pyc-objects">
        <div><code>product1</code><strong>K161</strong><small>stock = 3</small></div>
        <div><code>product2</code><strong>K162</strong><small>stock = 10</small></div>
      </div>
      <p>两个名字指向两个不同实例，各自拥有 stock 属性。</p>
    </section>
    <section class="pyc-state__method">
      <span>02 · 当前方法</span>
      <code>product1.add_stock(5)</code>
      <dl>
        <div><dt>self</dt><dd><code>→ product1</code></dd></div>
        <div><dt>quantity</dt><dd><code>→ 5</code></dd></div>
      </dl>
      <code>self.stock = self.stock + quantity</code>
      <p>代入当前对象：`3 + 5 → 8`。</p>
    </section>
    <section>
      <span>03 · 调用之后</span>
      <div class="pyc-objects">
        <div class="pyc-object--changed"><code>product1</code><strong>K161</strong><small>stock: 3 → 8</small></div>
        <div class="pyc-object--same"><code>product2</code><strong>K162</strong><small>stock: 10 → 10 · 未改变</small></div>
      </div>
      <p>方法只通过 self 修改 product1，没有访问 product2。</p>
    </section>
  </div>
</figure>

方法可以读取当前实例的属性：

```python
def need_restock(self):
    return self.stock < 5
```

`product1.need_restock()` 中的 `self.stock` 读取 product1 当前的库存；`product2.need_restock()` 则读取 product2 的库存。调用者不传 `self`，但需要通过具体实例调用方法。

<Callout title="类没有让数据自动隔离">
  本例的独立性来自 product1 和 product2 是两个不同实例，并且 stock 是各自的实例属性。不要把结论扩大成“类里的所有数据都一定互不影响”；本选修章只使用最直接的实例属性。
</Callout>

## 什么时候应该停留在字典和函数

继续使用字典和函数，通常更适合：

- 数据直接来自 JSON，只需读取、筛选、转换后写出。
- 脚本很短，数据只是一次性中间结果。
- 只有一两个简单操作，函数参数已经清楚。
- 类只会包住一个乘法或一条判断，没有长期状态。

可以考虑类的信号是：

- 同一种实体会创建很多个实例。
- 每个实例需要在程序运行期间持续保存、改变自己的状态。
- 多个方法都围绕同一组属性工作。
- `product.add_stock(5)` 这种调用比反复传字典更符合业务阅读方式。

不要为了一个乘法创建 `AmountCalculator`，也不要把每个字典都机械转换成对象。类增加了定义、初始化和方法调用三层结构，只有它们换来了更清楚的状态边界才值得。
