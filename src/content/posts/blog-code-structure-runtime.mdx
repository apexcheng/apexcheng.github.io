## 从 URL 反查：页面文件就是路由入口

<section class="run-board run-board--routes" aria-label="URL 到 Astro 页面入口映射">
  <header class="run-board-head">
    <div>
      <span class="run-index">R01 · ROUTE TABLE</span>
      <strong class="run-board-title">先把访问路径翻译成 <code>{`src/pages`}</code> 下的文件</strong>
    </div>
    <p>Astro 使用文件路由；静态页面直接对应文件，方括号目录或文件名表示构建时生成的动态参数路径。</p>
  </header>

  <div class="run-route-table">
    <div class="run-route-head">
      <span>浏览器 URL</span>
      <span>页面入口</span>
      <span>构建职责</span>
    </div>
    <article>
      <code>{`/`}</code>
      <strong><code>{`src/pages/index.astro`}</code></strong>
      <p>当前转交给 <code>{`home-redesign-1.astro`}</code> 渲染首页。</p>
    </article>
    <article>
      <code>{`/articles/`}</code>
      <strong><code>{`src/pages/articles/index.astro`}</code></strong>
      <p>读取公开文章，组织分类、标签、排序与文章列表。</p>
    </article>
    <article>
      <code>{`/articles/{slug}/`}</code>
      <strong><code>{`src/pages/articles/[...slug].astro`}</code></strong>
      <p>用 <code>{`getStaticPaths()`}</code> 为每篇公开文章生成详情路径。</p>
    </article>
    <article>
      <code>{`/articles/category/{category}/`}</code>
      <strong><code>{`src/pages/articles/category/[category].astro`}</code></strong>
      <p>为固定分类生成聚合页。</p>
    </article>
    <article>
      <code>{`/articles/tag/{tag}/`}</code>
      <strong><code>{`src/pages/articles/tag/[tag].astro`}</code></strong>
      <p>从公开文章标签生成聚合路径。</p>
    </article>
    <article>
      <code>{`/series/{series}/`}</code>
      <strong><code>{`src/pages/series/[series].astro`}</code></strong>
      <p>按 series 元数据和文章顺序生成系列页。</p>
    </article>
    <article>
      <code>{`/rss.xml`}</code>
      <strong><code>{`src/pages/rss.xml.ts`}</code></strong>
      <p>把公开文章映射为 RSS item。</p>
    </article>
  </div>

  <footer class="run-verdict">
    <span>LOCATE</span>
    <strong>页面问题先从 URL 找 <code>{`src/pages`}</code>；不要先钻进组件或文章正文。</strong>
  </footer>
</section>

## 文章怎样进入 Content Collection

<section class="run-board run-board--collection" aria-label="文章 Content Collection 入库与过滤流程">
  <header class="run-board-head">
    <div>
      <span class="run-index">R02 · CONTENT INTAKE</span>
      <strong class="run-board-title">Markdown / MDX 文件先通过 schema，再被页面读取、过滤和排序</strong>
    </div>
    <p><code>{`src/content.config.ts`}</code> 是文章字段的代码边界；分类与系列合法值分别来自 <code>{`src/data/categories.ts`}</code> 和 <code>{`src/data/series.ts`}</code>。</p>
  </header>

  <div class="run-intake-flow">
    <article>
      <span>SOURCE</span>
      <strong><code>{`src/content/posts/**/*.{md,mdx}`}</code></strong>
      <p>正文与 frontmatter 一起进入 posts collection。</p>
    </article>
    <i aria-hidden="true"></i>
    <article>
      <span>SCHEMA</span>
      <strong><code>{`defineCollection({ type: 'content' })`}</code></strong>
      <p>Zod 校验字段类型、默认值、合法分类与系列 ID。</p>
    </article>
    <i aria-hidden="true"></i>
    <article>
      <span>QUERY</span>
      <strong><code>{`getCollection('posts')`}</code></strong>
      <p>页面、布局和 RSS 从同一个集合读取文章。</p>
    </article>
    <i aria-hidden="true"></i>
    <article>
      <span>PUBLIC FILTER</span>
      <strong><code>{`!draft && !private`}</code></strong>
      <p>公开入口统一排除草稿和私密文章。</p>
    </article>
  </div>

  <div class="run-schema-map">
    <article>
      <span>IDENTITY</span>
      <strong><code>{`title · description · date · updated?`}</code></strong>
      <p>标题、摘要与时间信息。</p>
    </article>
    <article>
      <span>INDEX</span>
      <strong><code>{`category · tags · minutes · featured`}</code></strong>
      <p>分类、检索、阅读时间与精选状态。</p>
    </article>
    <article>
      <span>SERIES</span>
      <strong><code>{`series? · seriesOrder?`}</code></strong>
      <p>可选系列 ID 与正整数顺序。</p>
    </article>
    <article>
      <span>BOUNDARY</span>
      <strong><code>{`draft · private`}</code></strong>
      <p>两个字段默认都是 <code>{`false`}</code>；公开页面同时过滤两者。</p>
    </article>
  </div>

  <div class="run-code-pair">
    <div>
      <span>集合定义（节选）</span>
      <pre><code>{`const posts = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    category: z.enum(categories),
    draft: z.boolean().default(false),
    private: z.boolean().default(false),
  }),
});`}</code></pre>
    </div>
    <div>
      <span>公开读取（实际模式）</span>
      <pre><code>{`const posts = (await getCollection('posts'))
  .filter((post) => !post.data.draft && !post.data.private)
  .sort((a, b) => b.data.date.valueOf() - a.data.date.valueOf());`}</code></pre>
    </div>
  </div>
</section>

schema 能确认字段是否合法，页面过滤决定内容是否进入公开入口。两者解决的是不同问题：前者阻止结构错误，后者实施发布边界。

## 一篇 MDX 详情页怎样完成渲染

<section class="run-board run-board--render" aria-label="文章详情页 MDX 渲染栈">
  <header class="run-board-head">
    <div>
      <span class="run-index">R03 · RENDER STACK</span>
      <strong class="run-board-title">路径在构建期确定，正文再与组件、布局和全局样式合并</strong>
    </div>
    <p>详情页入口是 <code>{`src/pages/articles/[...slug].astro`}</code>。它既负责生成路径，也负责渲染文章与系列导航。</p>
  </header>

  <div class="run-render-stack">
    <article class="run-layer run-layer--path">
      <span>L1 · PATH</span>
      <div>
        <strong><code>{`getStaticPaths()`}</code></strong>
        <p>读取公开 posts，把每篇 <code>{`post.slug`}</code> 映射为静态路径和 props。</p>
      </div>
      <code>{`params: { slug: post.slug }`}</code>
    </article>
    <article class="run-layer run-layer--content">
      <span>L2 · CONTENT</span>
      <div>
        <strong><code>{`render(post)`}</code></strong>
        <p>返回正文组件 <code>{`Content`}</code> 与标题数据 <code>{`headings`}</code>。</p>
      </div>
      <code>{`const { Content, headings } = await render(post);`}</code>
    </article>
    <article class="run-layer run-layer--mdx">
      <span>L3 · MDX</span>
      <div>
        <strong>Markdown + Astro components</strong>
        <p>MDX integration 让正文保留 Markdown，同时导入文章专属或现有 Astro 组件。</p>
      </div>
      <code>{`integrations: [mdx()]`}</code>
    </article>
    <article class="run-layer run-layer--layout">
      <span>L4 · LAYOUT</span>
      <div>
        <strong><code>{`SiteLayout.astro`}</code> + <code>{`[...slug].astro`}</code></strong>
        <p>SiteLayout 提供导航、搜索、主题与站点外壳；文章路由组织侧栏、正文和深度为 2 或 3 的目录 headings。</p>
      </div>
      <code>{`<Content />`}</code>
    </article>
    <article class="run-layer run-layer--style">
      <span>L5 · STYLE</span>
      <div>
        <strong><code>{`src/styles/global.css`}</code> + article CSS</strong>
        <p>全局文件控制站点外壳；单篇独有信息图用文章 class 限定，避免污染其他页面。</p>
      </div>
      <code>{`html[data-theme='dark']`}</code>
    </article>
  </div>

  <div class="run-render-output">
    <span>BUILD RESULT</span>
    <strong>每篇公开文章得到一个静态详情页</strong>
    <p>浏览器收到的是已经生成的 HTML、CSS 与必要脚本；不会在每次访问时重新查询文章数据库。</p>
  </div>
</section>

MDX 组件不是独立应用层。它们在构建时成为文章渲染树的一部分；页面外壳与全局主题仍由 SiteLayout 和 global.css 负责。

## 静态构建怎样把所有入口合成产物

<section class="run-board run-board--build" aria-label="Astro 静态构建工厂蓝图">
  <header class="run-board-head">
    <div>
      <span class="run-index">R04 · BUILD FACTORY</span>
      <strong class="run-board-title">一次 build 同时处理页面路由、文章路径、组件依赖和公开资源</strong>
    </div>
    <p>当前 <code>{`astro.config.mjs`}</code> 配置站点地址并启用 MDX，没有配置 <code>{`base`}</code>；输出沿 Astro 当前默认静态站点方式生成。</p>
  </header>

  <div class="run-build-grid">
    <div class="run-build-inputs">
      <article><span>ROUTES</span><strong><code>{`src/pages/`}</code></strong><p>固定入口与参数化入口</p></article>
      <article><span>CONTENT</span><strong><code>{`posts collection`}</code></strong><p>公开文章与 frontmatter</p></article>
      <article><span>UI</span><strong><code>{`components · layouts · styles`}</code></strong><p>渲染能力与主题</p></article>
      <article><span>ASSETS</span><strong><code>{`public/`}</code></strong><p>按原路径复制的公开文件</p></article>
    </div>
    <i class="run-build-arrow" aria-hidden="true"></i>
    <article class="run-build-engine">
      <span>ASTRO BUILD</span>
      <strong>解析 → 校验 → 渲染 → 生成</strong>
      <p>Content schema 先检查文章；页面收集路径；MDX 与 Astro 组件编译；静态入口写入产物目录。</p>
      <pre><code>{`npm run build`}</code></pre>
    </article>
    <i class="run-build-arrow" aria-hidden="true"></i>
    <div class="run-build-outputs">
      <article><span>HTML</span><strong>页面与文章</strong></article>
      <article><span>CSS / JS</span><strong>样式与必要交互</strong></article>
      <article><span>PUBLIC</span><strong>公开静态资源</strong></article>
      <article><span>RSS</span><strong><code>{`rss.xml`}</code></strong></article>
    </div>
  </div>

  <div class="run-build-boundary">
    <div>
      <span>构建前错误</span>
      <strong>frontmatter、MDX 语法、导入路径或页面代码可让 build 失败。</strong>
    </div>
    <div>
      <span>构建后边界</span>
      <strong>产物用于托管；下一次内容修改仍应回到源码，而不是手改 <code>{`dist/`}</code>。</strong>
    </div>
  </div>
</section>

## 出问题时按现象定位代码，不要从根目录盲找

<section class="run-board run-board--locator" aria-label="博客代码问题定位矩阵">
  <header class="run-board-head">
    <div>
      <span class="run-index">R06 · CODE LOCATOR</span>
      <strong class="run-board-title">先问“哪里表现错了”，再沿最短链路找到责任文件</strong>
    </div>
    <p>下面不是完整目录说明，而是从现象到入口、继续追踪点和验证动作的最短排查图。</p>
  </header>

  <div class="run-locator-grid">
    <article>
      <span>现象 01 · 某个 URL 不对</span>
      <strong>先看 <code>{`src/pages/`}</code></strong>
      <p>按访问路径找到同名页面；参数路由继续看 <code>{`getStaticPaths()`}</code>。</p>
      <small>验证：build 是否生成对应路径</small>
    </article>
    <article>
      <span>现象 02 · 文章没出现</span>
      <strong>先看 frontmatter 与公开过滤</strong>
      <p>检查 schema、<code>{`draft`}</code>、<code>{`private`}</code>、分类、系列与页面过滤条件。</p>
      <small>验证：collection 读取与列表结果</small>
    </article>
    <article>
      <span>现象 03 · 正文或目录异常</span>
      <strong>先看详情页与目标 MDX</strong>
      <p>确认 <code>{`render(post)`}</code>、<code>{`<Content />`}</code>、H2/H3 headings 和组件 import。</p>
      <small>验证：单篇编译与实际页面</small>
    </article>
    <article>
      <span>现象 04 · 全站视觉异常</span>
      <strong>先看 Layout 与 global.css</strong>
      <p>导航、主题和文章外壳属于全局；单篇信息图只排查文章专属 class。</p>
      <small>验证：浅色、深色与 390px 页面</small>
    </article>
    <article>
      <span>现象 05 · 本地能看、build 失败</span>
      <strong>先看构建输出的首个错误</strong>
      <p>沿文件和行号检查 MDX 语法、导入路径、schema 与构建期代码。</p>
      <small>验证：<code>{`npm test`}</code> + <code>{`npm run build`}</code></small>
    </article>
    <article>
      <span>现象 06 · build 通过、线上没变</span>
      <strong>再看 Actions 与 Pages</strong>
      <p>确认 main 推送、build/deploy jobs、Pages Source 和实际访问结果。</p>
      <small>状态：需运行验证</small>
    </article>
  </div>

  <div class="run-final-route">
    <span>RUNTIME TAKEAWAY</span>
    <strong>URL 找 page，文章找 collection，展示找 render / component / layout，产物找 build，线上找 workflow 与 Pages。</strong>
    <p>需要理解这些文件为何这样分区，再回到系列上一篇的系统蓝图；需要修代码，则继续沿本篇的最短执行链定位。</p>
  </div>
</section>
