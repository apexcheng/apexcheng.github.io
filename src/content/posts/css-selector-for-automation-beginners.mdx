刚开始学自动化，CSS 定位很容易被讲成“背几个语法”。真实项目里更重要的问题是：这个选择器能不能长期命中正确元素，失效后能不能快速知道原因。

本文面向网页自动化场景，尤其是影刀编码版常见的 `browser.find_by_css()`、`browser.find_all_by_css()` 和 `browser.find_by_xpath()`。临时操作可以只求能用；交给 RPA 长期运行时，定位必须像代码一样可读、可验证、可维护。

## 稳定定位到底在解决哪几层问题？

只会写选择器，解决的是“能否命中”；能把范围、唯一性和页面上下文一起考虑，才是在解决自动化稳定性。

## 基础选择器怎么选，才不会一开始就走偏？

基础语法不需要死背。先判断元素有没有“表达功能的稳定特征”，再决定用 id、class 还是属性。

  <div class="selector-board-head">
    <div><span>02 · SELECTOR INDEX</span><strong>六种入口，一条优先级</strong></div>
    <p>越靠近业务语义，通常越适合自动化；越依赖位置和样式，维护风险越高。</p>
  </div>
  <div class="selector-index">
    <div class="selector-index-axis"><span>更稳定</span><i></i><span>更依赖页面结构</span></div>
    <div class="selector-index-items">
      <div><b>属性</b><code>input[name="username"]</code><small>`name`、稳定且表达业务或测试语义的 `data-*`、`aria-label` 优先</small></div>
      <div><b>id</b><code>#submit-order</code><small>仅在 id 稳定且唯一时使用</small></div>
      <div><b>组合</b><code>input.form-input[name="keyword"]</code><small>单条件不唯一时补必要条件</small></div>

## 六种属性匹配分别该在什么时候用？

页面没有干净的 id 或专用测试属性时，关键不是立即改用长路径，而是识别属性值中哪一部分稳定。

<div class="selector-manual" role="group" aria-label="CSS 属性匹配刻度尺">
  <div class="selector-board-head">
    <div><span>03 · ATTRIBUTE GAUGE</span><strong>属性匹配刻度尺</strong></div>
    <p>从精确到宽松，匹配范围逐渐扩大；越宽松，越需要范围控制和数量验证。</p>
  </div>
  <div class="selector-gauge">
    <div class="selector-gauge-line"><span>窄</span><i></i><span>宽</span></div>
    <div class="selector-gauge-grid">
      <div class="is-safe"><b>=</b><strong>完全等于</strong><code>[data-action="submit"]</code><small>属性值完整且稳定</small></div>
      <div><b>^=</b><strong>固定开头</strong><code>[id^="order-"]</code><small>前缀稳定、后半段变化</small></div>
      <div><b>$=</b><strong>固定结尾</strong><code>[href$=".xlsx"]</code><small>文件名或状态后缀稳定</small></div>
      <div class="is-caution"><b>&#42;=</b><strong>包含片段</strong><code>[class*="comments--"]</code><small>动态值中间有稳定语义</small></div>
      <div><b>&#126;=</b><strong>空格分词</strong><code>[class~="primary"]</code><small>属性由多个独立词组成</small></div>
      <div><b>|=</b><strong>词或词前缀</strong><code>[lang|="zh"]</code><small>等于 `zh` 或以 `zh-` 开头</small></div>
    </div>
  </div>
  <div class="selector-compare-lab">
    <div>
      <span class="selector-chip selector-chip--orange">动态 class</span>
      <pre><code class="language-html">{`<div class="comments--ChxC7GEN">评价区</div>`}</code></pre>
      <p>随机后缀会变化，稳定片段是 `comments--`。</p>
    </div>
    <div class="selector-compare-arrow">→</div>
    <div>
      <span class="selector-chip selector-chip--green">候选写法</span>
      <code>div[class*="comments--"]</code>
      <p>可用于收窄候选，但必须检查匹配数量。</p>
    </div>
  </div>
  <div class="selector-word-test">
    <div><code>[class~="primary"]</code><span>✓</span><small>class="button primary large"</small></div>
    <div><code>[class~="primary"]</code><span>✓</span><small>class="primary"</small></div>
    <div class="is-fail"><code>[class~="primary"]</code><span>×</span><small>class="primary-button"</small></div>
  </div>
  <div class="selector-board-verdict selector-board-verdict--warning">
    <span>风险边界</span>
    <strong>`*=` 不是更高级，只是更宽松。能精确匹配时不要先用模糊匹配。</strong>
  </div>
</div>

批量选择器可以先拿到候选，再按文本、状态或其它属性筛选：

```python
rows = browser.find_all_by_css('tr[data-order-id^="202607"]', timeout=10)
```

## 关系选择器和伪类，什么时候是在帮忙，什么时候在添风险？

关系选择器负责表达“元素在哪个容器、哪一层、哪个相邻位置”；伪类负责表达“元素是什么状态或位置”。它们解决的问题不同。

<div class="selector-manual" role="group" aria-label="DOM 关系地图和伪类风险带">
  <div class="selector-board-head">
    <div><span>04 · DOM RELATION MAP</span><strong>先看关系，再评估结构依赖</strong></div>
    <p>业务容器通常比页面位置稳定；位置型伪类通常比属性状态更脆弱。</p>
  </div>
  <div class="selector-dom-map">
    <div class="selector-dom-tree">
      <div class="selector-dom-node selector-dom-node--root"><code>.dialog</code><small>业务容器 A</small></div>
      <div class="selector-dom-branch">
        <div class="selector-dom-node"><code>.toolbar</code><small>直接子元素 B</small></div>
        <div class="selector-dom-node"><code>label</code><small>相邻参照 A</small></div>
        <div class="selector-dom-node selector-dom-node--target"><code>input</code><small>目标元素 B</small></div>
        <div class="selector-dom-node"><code>button</code><small>后续同级 B</small></div>
      </div>
    </div>
    <div class="selector-dom-legend">
      <div><code>A B</code><strong>任意后代</strong><span>.dialog button</span><small>最常用的范围控制</small></div>
      <div><code>A &gt; B</code><strong>直接子元素</strong><span>.menu &gt; li</span><small>避免继续命中深层元素</small></div>
      <div><code>A + B</code><strong>紧邻兄弟</strong><span>label + input</span><small>依赖相邻结构，改版可能失效</small></div>
      <div><code>A ~ B</code><strong>后续同级</strong><span>.title ~ button</span><small>命中 A 后面的所有同级 B</small></div>
    </div>
  </div>
  <div class="selector-risk-band">
    <div class="is-low"><b>低风险</b><code>:checked</code><code>:disabled</code><small>状态明确，适合判断控件状态</small></div>
    <div class="is-mid"><b>中风险</b><code>:not(...)</code><code>:first-child</code><small>适合排除干扰或固定结构</small></div>
    <div class="is-high"><b>高风险</b><code>:nth-child(n)</code><code>:last-child</code><small>数据和顺序变化时容易错位</small></div>
    <div class="is-runtime"><b>需运行验证</b><code>:has(...)</code><small>表达力强，但要确认影刀实际运行环境支持</small></div>
  </div>
  <div class="selector-has-case">
    <code>tr:has([data-status="待处理"]) button.process</code>
    <p>语义是“找到包含待处理状态的表格行，再取这一行的处理按钮”。如果能用订单 id 直接定位，就不必为了复杂而使用 `:has()`。</p>
  </div>
  <div class="selector-board-verdict">
    <span>使用原则</span>
    <strong>范围关系优先服务业务语义；结构关系和位置伪类只在没有更稳定特征时使用。</strong>
  </div>
</div>

## 写一个选择器时，应该按什么顺序下手？

不要从浏览器复制路径开始。把定位当成一次从业务区域到唯一元素的逐层诊断。

<div class="selector-manual selector-manual--dark" role="group" aria-label="CSS 定位四步仪表盘">
  <div class="selector-board-head">
    <div><span>05 · LOCATOR PROCEDURE</span><strong>四步定位仪</strong></div>
    <p>每一步都有输入、动作和退出条件；任何一步信息不足，都先回页面确认。</p>
  </div>
  <div class="selector-procedure">
    <div class="selector-procedure-step">
      <b>01</b><span class="selector-procedure-icon">◎</span>
      <div><strong>确定区域</strong><p>页面主体、弹窗、表格、商品卡片</p><small>退出条件：业务容器已明确</small></div>
    </div>
    <div class="selector-procedure-step">
      <b>02</b><span class="selector-procedure-icon">⌕</span>
      <div><strong>寻找稳定特征</strong><p>id、name、具备业务或测试语义的 data-*、aria-label</p><small>退出条件：特征稳定且能表达功能</small></div>
    </div>
    <div class="selector-procedure-step">
      <b>03</b><span class="selector-procedure-icon">✣</span>
      <div><strong>组合必要条件</strong><p>只补足能消除歧义的条件</p><small>退出条件：选择器仍然短且可读</small></div>
    </div>
    <div class="selector-procedure-step">
      <b>04</b><span class="selector-procedure-icon">✓</span>
      <div><strong>验证匹配数量</strong><p>0 个、1 个、多个分别处理</p><small>退出条件：目标唯一且语义正确</small></div>
    </div>
  </div>
  <div class="selector-priority-console">
    <div><span>优先级</span><b>1</b><strong>稳定且表达业务或测试语义的 data-* / name / aria-label</strong></div>
    <div><span>优先级</span><b>2</b><strong>稳定且有意义的 id</strong></div>
    <div><span>优先级</span><b>3</b><strong>稳定且有意义的 class</strong></div>
    <div><span>优先级</span><b>4</b><strong>标签 + 属性组合</strong></div>
    <div class="is-last"><span>最后考虑</span><b>5</b><strong>nth-child</strong></div>
  </div>
  <div class="selector-procedure-alerts">
    <span>× 复制超长路径</span><span>× 只靠随机 class</span><span>× 模糊匹配不验数量</span>
  </div>
</div>

这张定位仪就是写代码时的检查顺序：先确认范围和稳定特征，再组合，最后把数量验证写进程序。

## CSS、XPath 和 get_text() 应该怎么分工？

CSS 是主力定位方式，但不是唯一方式。只有显示文字稳定时，硬凑 CSS 往往会把问题复杂化。

<div class="selector-manual" role="group" aria-label="CSS XPath 和文字筛选路由">
  <div class="selector-board-head">
    <div><span>06 · ROUTING CONSOLE</span><strong>定位方式路由台</strong></div>
    <p>先判断稳定信息来自属性、文字还是页面上下文，再选工具。</p>
  </div>
  <div class="selector-router">
    <div class="selector-router-start"><span>START</span><strong>目标元素有什么稳定信息？</strong></div>
    <div class="selector-router-paths">
      <div>
        <span class="selector-chip selector-chip--blue">稳定属性</span>
        <strong>优先 CSS</strong>
        <code>button[data-action="submit"]</code>
        <small>短、清楚，适合范围组合</small>
      </div>
      <div>
        <span class="selector-chip selector-chip--orange">只有文字</span>
        <strong>改用 XPath</strong>
        <code>//button[normalize-space(.)="提交订单"]</code>
        <small>标准 CSS 不能匹配内部文字</small>
      </div>
      <div>
        <span class="selector-chip selector-chip--violet">先限范围再看文字</span>
        <strong>CSS + get_text()</strong>
        <code>.order-dialog button</code>
        <small>先拿候选，再在 Python 中筛选</small>
      </div>
      <div>
        <span class="selector-chip selector-chip--red">上下文异常</span>
        <strong>先处理页面状态</strong>
        <code>iframe / popup / async</code>
        <small>加载、弹窗和 iframe 不是选择器语法问题</small>
      </div>
    </div>
  </div>
  <div class="selector-invalid-css">
    <div><span>不能匹配内部文字</span><code>button[text="提交订单"]</code></div>
    <div><span>非标准 / 无效 CSS</span><code>button:contains("提交订单")</code></div>
    <strong>前者是合法属性选择器，但只会检查 `text` 属性；后者不是标准 CSS。</strong>
  </div>
  <div class="selector-board-verdict">
    <span>分工结论</span>
    <strong>CSS 缩小结构范围，XPath 处理稳定文字，get_text() 在候选集合中完成业务筛选。</strong>
  </div>
</div>

按文字直接定位：

```python
button = browser.find_by_xpath(
    '//button[normalize-space(.)="提交订单"]',
    timeout=10,
)
button.click()
```

先限定弹窗，再按文字筛选：

```python
buttons = browser.find_all_by_css(".order-dialog button", timeout=10)

for button in buttons:
    if button.get_text().strip() == "提交订单":
        button.click()
        break
else:
    raise RuntimeError('未找到文本为“提交订单”的按钮')
```

## 怎样验证唯一性，并判断“找不到”到底是哪一层出了问题？

先在开发者工具中确认 HTML 和匹配数量，再进入影刀运行环境。这样可以把“选择器语法”和“页面状态”分开排查。

  <div class="selector-board-head">

    <p>一个选择器至少要通过“语法、数量、语义、运行环境”四道检查。</p>

  <div class="selector-validation-flow">
    <div><b>1</b><strong>检查元素</strong><span>F12 → Inspect</span><small>观察标签、id、class、name、data-*、aria-label</small></div>

## 坏定位应该怎样一步步改造成可维护定位？

改造方向不是“换一个更复杂的语法”，而是减少结构依赖，增加业务语义，并让结果可验证。

    <p>从原始页面特征出发，逐步替换不稳定依赖，而不是记固定答案。</p>

areas = browser.find_all_by_css('div[class*="comments--"]', timeout=10)

如果弹窗没有 `data-action`，但文字稳定，可以退回 CSS 候选加文字筛选：

```python
buttons = browser.find_all_by_css(".order-dialog button", timeout=10)

for button in buttons:
    if button.get_text().strip() == "确认":

    raise RuntimeError("未找到弹窗里的确认按钮")
```
