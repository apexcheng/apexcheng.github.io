先纠正一个容易混淆的说法：`VALUE` 不是“把字符串转成文本”，而是**把看起来像数字的文本，解析成真正的数值**。

例如单元格里保存的是文本 `"123.45"`，它看起来像数字，但未必能正常参与求和、排序或比较。使用 `=VALUE("123.45")` 后，Excel 返回数值 `123.45`。

## 一、Excel 实际检查了什么

以文本 `" -1,234.56 "` 为例，`VALUE` 会把它拆成有意义的数字结构，而不是简单删除其中的符号。

这里的关键不是“文字长得像数字”，而是 Excel 能否按照数字格式把整段文字解释完整。解析成功后，结果就不再是逐个字符，而是一个真正的数值。

## 二、为什么转换后才能正常计算

文本和数值在 Excel 里是两种不同的数据类型。它们在单元格里可能看起来完全一样，但参与公式时的行为不同。

<div class="value-type-compare" role="group" aria-label="文本数字和真正数值的区别">
  <article>
    <span>转换前 · 文本</span>
    <strong>"123.45"</strong>
    <ul>
      <li>本质是一串字符</li>
      <li>可能被求和函数忽略</li>
      <li>排序时可能按文字顺序处理</li>
    </ul>
  </article>
  <i>VALUE</i>
  <article class="is-number">
    <span>转换后 · 数值</span>
    <strong>123.45</strong>
    <ul>
      <li>可以直接加减乘除</li>
      <li>可以参与统计和比较</li>
      <li>可以继续设置货币、百分比等显示格式</li>
    </ul>
  </article>
</div>

需要注意：**单元格显示格式不会改变数据类型。**把文本单元格设置为“数值格式”，只是改变显示规则，并不会自动把文本转换成数值；`VALUE` 才是在转换实际内容。

## 三、几个典型例子

| 公式 | Excel 识别过程 | 返回结果 |
| --- | --- | ---: |
| `=VALUE("123")` | 识别为整数 | `123` |
| `=VALUE(" +45.6 ")` | 忽略首尾空格，识别正号和小数 | `45.6` |
| `=VALUE("1,234.56")` | 按当前地区设置识别千位符和小数点 | `1234.56` |
| `=VALUE("-0.75E2")` | 识别科学计数法 | `-75` |
| `=VALUE("12a3")` | 包含无法解释的字符 | `#VALUE!` |

如果来源数据使用的分隔符与当前 Excel 地区设置不同，可以使用 `NUMBERVALUE` 明确指定小数点和千位分隔符。例如：

```text
=NUMBERVALUE("1.234,56", ",", ".")
```

这个公式明确规定：逗号是小数点，句点是千位分隔符，最终返回数值 `1234.56`。

## 四、怎么判断转换成功

转换后的结果应该满足三个条件：

1. 能正常参与 `SUM`、加减乘除等计算。
2. 修改数字格式后，可以显示为货币、百分比或指定小数位。
3. 公式栏中保存的是数值，而不是前面带英文单引号的文本。

<HighlightBox eyebrow="核心原理" title="VALUE 本质上是一个数字解析器">
  它先判断文本是否符合数字格式，再把其中的符号、整数和小数解释成一个数值。合法就返回数值，不合法就返回 <code>#VALUE!</code>。所以它改变的不是外观，而是数据类型。
</HighlightBox>
